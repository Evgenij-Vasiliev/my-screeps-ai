Screeps Absolute Control Architecture

1. Общая концепция
   Система строится как гибрид:
   Автоматическая система (Autopilot) выполняет рутинные задачи
   Консоль управления (Console API) полностью перехватывает управление при необходимости
   Memory является единственным источником состояния
   Override-команды имеют максимальный приоритет

2. Принципы управления
   2.1 Двойной режим управления
   AUTO — стандартная работа системы
   OVERRIDE — ручное управление из консоли
   Override всегда имеет приоритет над AUTO.

2.2 Типы команд
Одноразовые команды
выполняются до завершения цели
после завершения возвращают управление AUTO
Постоянные режимы
действуют до ручной отмены
влияют на поведение автосистемы

2.3 Приоритеты
Override (консоль)
Creep-level команды
Group-level команды
Room-level команды
Empire-level команды
AutoTask

3. Архитектура модулей
   3.1 Kernel
   Точка входа системы, запускает все подсистемы каждый tick.
   3.2 Memory Layer
   Источник истины:
   autoTask
   overrideTask
   состояния комнат
   состояния крипов
   группы

3.3 Console API
Управляющий слой:
Empire._
Room._
Creep._
Group._
Работает только через запись в Memory.

3.4 Scheduler
Определяет, что выполнять:
проверяет override
применяет lock-состояния
выбирает активную задачу

3.5 Executor
Исполняет действия крипов без принятия решений.

3.6 Autopilot
Генерирует autoTask, не вмешивается в override.

5. Жизненный цикл крипа
   Проверка overrideTask
   Если нет — выполнение autoTask
   Выполнение действия
   Обновление состояния
   При завершении override → lock-frame → возврат к AUTO

6. Lock-frame механизм
   После завершения override:
   autoTask замораживается на 1 tick
   предотвращает дребезг логики
   стабилизирует переход

7. Движок приоритетов
   Каждое действие имеет приоритет:
   AUTO = 0
   Room = 1
   Group = 2
   Creep = 3
   Empire = 4
   Override = 5
   Всегда выполняется задача с максимальным приоритетом.

8. Диагностический слой
   Не влияет на поведение системы.
   Функции:
   трассировка действий крипов
   причины выбора задач
   состояние комнат и империи
   конфликт override/auto

9. Масштабирование
   Управление осуществляется через:
   группы крипов
   уровни комнат
   имперские команды
   Система не управляет объектами напрямую, а управляет наборами объектов.

10. Основной принцип
    Автосистема — фон
    Консоль — управление
    Memory — истина
    Scheduler — арбитр
    Executor — исполнитель
    Screeps Absolute Control — интеграция (текущее состояние)
11. Контекст системы
    Империя уже существует и работает (5 комнат, RCL8)
    Есть устоявшаяся архитектура:
    room.manager
    creep.runner
    role.\*
    Переписывание системы не выполняется

12. Подход к изменению
    Добавлен надстроечный CONTROL LAYER:
    не заменяет существующую систему
    работает поверх неё
    использует Memory как слой управления

13. Механизм управления (override)
    3.1 Новое поле в Memory
    Memory.creeps[id].override

3.2 Смысл
хранит команду ручного управления
временно заменяет поведение роли
имеет максимальный приоритет

4. Место интеграции
   Изменение внесено только в:
   creep.runner

5. Логика выполнения крипа
   Приоритет:
   override (консольное управление)
   auto role (старый AI)

6. Обновлённый цикл обработки крипа
   if override exists:
   execute override
   else:
   execute role logic

7. Override execution layer
   Функция:
   runOverride(creep, ov)

Поддерживаемые действия:
move
transfer
attack
heal

8. Поведение override
   имеет абсолютный приоритет над auto
   выполняется до завершения задачи
   после выполнения очищается (если одноразовый режим)

9. Поведение auto системы
   работает без изменений
   не знает о существовании override
   используется только при отсутствии override

10. Итоговая архитектура
    main
    → room.manager
    → creep.runner
    → override (если есть)
    → role.run() (если нет override)

11. Результат внедрения
    Система не переписана
    Добавлен слой абсолютного управления
    Возможность вмешиваться в любого крипа через Memory
    Автономная система сохранена полностью
    Гибридная модель AUTO + CONTROL

12. Итоговое состояние
    legacy AI: сохранён
    control layer: добавлен
    override: активен
    управление: теперь возможно в реальном времени
