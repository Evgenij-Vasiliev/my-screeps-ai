# Оценка проекта newScreeps — 24.09.2026

- **Что оценено:** ветка `Новая-Империя`, рабочее дерево **с незакоммиченными правками** (23 изменённых файла, +4078/−271, 2 untracked-модуля на 2091 строку).
- **Как проверено:** чтение кода и документации, `npx tsc --noEmit -p jsconfig.json`, `npx eslint .`, прогон всех `tests/*.test.js`, `git`-метрики, сканы на секреты/хардкод.
- **Оговорка:** оценки CPU взяты из живых замеров проекта (`docs/CPU-PROFILE.md`), не перемерялись; доход не проверялся.

## 1. Итоговая оценка

**7.5 / 10 — сильный, зрелый инженерный проект с дефектами процесса, а не архитектуры.**

Код здоровый: типы чисты, линтер чист, 28 из 29 тестовых файлов зелёные, лишний warning один.
Проблемы сосредоточены в трёх местах: (1) секрет и незакоммиченная работа, (2) тесты вне git и без раннера,
из-за чего документация уже разошлась с кодом, (3) рост монолитов и отсутствие реакции на `bucket` при
утилизации CPU ~50–57 %.

## 2. Что сделано хорошо

1. **Архитектура соответствует цели.** `main.js` (10 строк) → `empire.js` → `room.manager` → подсистемы.
   Нет scheduler/dispatcher/assignmentEngine — Task System ровно такой, каким описан в
   `docs/TASK_SYSTEM_ARCHITECTURAL_FOUNDATION.md`. Тяжёлые кэши вынесены из `Memory` в `heap`.
2. **Культура измерений.** `docs/CPU-PROFILE.md`, `PROJECT_AUDIT_AND_ROADMAP.md`, `SESSION_HANDOFF.md`
   содержат числа с живого шарда (окна тиков, мс/тик, доли), а не «стало быстрее».
   Гипотезы, которые не подтвердились, помечены как опровергнутые (например, «`roomState` — главный
   потребитель» → 9.46 %, 6-е место).
3. **Честность документации.** `SESSION_HANDOFF.md` §0.4 прямо пишет: «Эффект по доходу НЕ измерен»,
   «Замер счётчиков снять не успели». Это редкость и сильно повышает доверие к остальным числам.
4. **Инструментальная гигиена.** `tsc --noEmit` — чисто; `eslint` — 1 warning (`BOOST_ENERGY_PER_PART`
   не используется). 29 офлайн-тестовых файлов, тесты выводят ожидания из конфига (`CREEP_BODIES`,
   `BOOST_POLICY`), а не из литералов — это правильное решение, оно переживёт смену тел.
5. **Изоляция сбоев.** `room.manager.runRoom` обёрнут по подсистемам и по комнатам; инцидент
   «погасла E35S37» разобран до корневых причин и закрыт системно, а не оверрайдом.

## 3. Риски

### P0 — теряется работа и утёк секрет

1. **Утечка секрета — устранена (ротация 2026-09-24).** Ранее `Gruntfile.js:7` содержал токен
   деплоя Screeps, файл отслеживался git, и токен был в истории коммитов; тот же токен был вшит
   в 69 файлов `tests/_*.js` и `tests/live.*.js`. Утечка закрыта: токен отозван и перевыпущен,
   хардкод убран из `Gruntfile.js` и всех тестов (теперь `process.env.SCREEPS_TOKEN` или
   `.screeps.json` через `screeps.token.js`), а git-история перезаписана `git filter-repo
   --replace-text`. **Старый токен считать скомпрометированным навсегда.**
2. **Вся работа по бустам существует в одном экземпляре.** `boost.manager.js` (940 строк) и
   `lab.recipes.js` (1151 строка) — **untracked**; ещё 23 файла изменены и не закоммичены.
   `SESSION_HANDOFF.md` §0.6 признаёт это явно. `git checkout .`, сбой диска или случайный
   `git clean -fd` уничтожат ~2000 строк уникального кода и всю текущую незакоммиченную правку.
3. **Регрессионная защита вне контроля версий.** `tests/` целиком в `.gitignore` — 103 файла,
   включая все 29 офлайн-тестов. Тесты не бэкапятся, не ревьюятся, не видны в diff,
   и в CI их не будет по определению. Нет `npm test` (`package.json` → `echo "Error: no test specified"`),
   нет CI, нет pre-commit хука. Единственный способ запустить тесты — ручной shell-цикл из `SESSION_HANDOFF.md`.

### P1 — документация и код разошлись (уже сработало)

4. **Тест-дрейф.** Документация утверждает «26/26 зелёные». Факт на 24.09: **28 файлов зелёные, 1 падает**
   — `tests/factory.manager.test.js` (42 PASS / 1 FAIL). Падает он потому, что проверяет контракт
   «фабричный контур выключен» (`TASK_CONFIG.factory === false`), тогда как `constants.js:263` теперь
   `factory: true`. Это не баг кода, а **устаревший тест** — но именно тот класс дефекта, который
   закрывается CI и коммитом, а не существует месяцами.
5. **Вводящие в заблуждение комментарии.** `constants.js:263`: значение `factory: true`,
   а комментарий рядом — «(ВРЕМЕННО ВЫКЛ: иначе фабрика продолжает жечь энергию склада…)».
   Комментарий противоречит значению.
6. **`tsc` чистый, но доверие ложное.** `types.d.ts` неполный и широкий (`_HasId.store?: any`),
   много полей `CreepMemory`/`Memory` не объявлено (пункт 40 аудита от 16.09 всё ещё верен).
   Exit 0 достигается за счёт `any`, а не за счёт типизации.
7. **Нет реакции на `bucket`.** `Game.cpu.bucket` читается только для логирования
   (`cpuMonitor.js:190-203`), константа `CPU.BUCKET_CRITICAL = 500` (`constants.js:1523`)
   не гейтит ни одну подсистему. Пункт 10 аудита от 16.09 **не закрыт**. При просадке bucket
   ничего не отключается — движок просто остановит скрипт.

### P2 — производительность и рост

8. **Запас CPU тонкий.** `roomManager` 7.63 мс/тик (max 13.78) + `remoteManager` 1.73 (max 9.22),
   суммарно наблюдаемые 10.2–11.5 мс/тик при лимите 20. То есть средняя утилизация ~55 %,
   а пики одного `roomManager` уже 69 % бюджета. Рост с 16.09: `roomManager` 7.81 → 7.63 (шум),
   но появились новые блоки — `labWorker`+`labManager`+`boostManager` ≈ 2.07 мс/тик.
   Главные статьи по `docs/CPU-PROFILE.md`: `miner` ≈ 0.21 мс за вызов `harvest()`, буст-конвейер,
   `remoteManager`. Вывод проекта («CPU определяется числом вызовов методов-действий, а не объёмом JS»)
   подтверждён замерами и должен оставаться главным правилом.
9. **Рост монолитов без декомпозиции.** За 8 дней корневой JS вырос с ~5 870 до **14 924** строк:
   `constants.js` 1921, `market.manager.js` 1254, `terminalNetwork.js` 994, `lab.recipes.js` 1151,
   `task.executors.js` 956, `boost.manager.js` 940. `constants.js` уже содержит **функции**
   (`spawnTimeOf`, `longestRemoteRoute`, `remotePreSpawnThreshold`) — это уже не «единый модуль констант»,
   а модуль констант + логика. `market.manager.js` смешивает три независимые политики
   (продажа излишков, закупка X, импорт для лаб) + `run()`. Коэффициент связности растёт быстрее
   проекта — типичный предвестник «файла на 3000 строк, который страшно трогать».
10. **Хардкод состояния шарда.** ✅ **ИСПРАВЛЕНО 2026-09-25.** Списки комнат, ID линков,
    клетки контейнеров, маршруты дальних ролей, обход обсервера, комнаты риска и точка сбора
    вынесены в `Memory.empire` (`shard.state.js`), текущие значения `constants.REMOTE` /
    `constants.EMPIRE` работают defaults: `empire.js` вызывает `ensure()` каждый тик и
    дозаполняет ТОЛЬКО отсутствующие ключи, не затирая правки владельца. Потребители
    (`remote.manager`/`remote.hauler`/`remote.miner`/`remote.handoff`, `spawn.manager`,
    `observer.manager`, `defense.manager`, `defense.attacker`) больше не содержат строк комнат
    в коде. Порог пре-спавна дальних ролей считается от НАСТРОЕННЫХ комнат и маршрутов
    (`shard.state.preSpawnThreshold`), поэтому добавление комнаты в Memory не оставляет роль с
    заниженным порогом. Невалидный ID линка-приёмника даёт ОДИН явный лог (`warnOnce`) вместо
    тихого фолбэка в storage. Тест: `tests/shard.state.test.js` (39 проверок); контракт barrel
    обновлён (`EMPIRE`).
11. **`console.log` и мониторинг стоят CPU.** 60 вызовов `console.log` в продовых модулях;
    роль-CPU мониторинг по-прежнему делает 2 × `Game.cpu.getUsed()` **на каждого крипа каждого тика**
    (аудит п. 9). В Screeps вывод в консоль сам по себе тарифицируется.
    ✅ **Ролевая часть исправлена 2026-09-24:** ролевой замер — opt-in
    (`Memory.cpuMonitorRoles`, по умолчанию выключено), поэтому `getUsed` на крипа не
    вызывается вовсе; при включении — один тик из `CPU.SAMPLE_INTERVAL` (7) и одна
    строка раз в `CPU.ROLE_REPORT_INTERVAL` (50) тиков. Остаётся `console.log` в
    горячих путях ролей (отдельная задача).

## 5. Вердикт

Проект в хорошей форме: архитектура выдержала рост с 5.9k до 14.9k строк и разбор двух инцидентов
без переписывания. Основной риск — **не код, а процесс**: секрет в истории, вся новая работа вне git,
тесты вне git и без раннера. Пункты 1–5 стоят меньше половины дня и закрывают почти весь P0–P1.
Главный содержательный долг — CPU-бюджет (55 % утилизации, пики 69 %, `bucket` не защищает) и
доказательство эффекта по доходу, который документация честно называет неизмеренным.
