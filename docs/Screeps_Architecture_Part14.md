# Screeps — Архитектура зрелой империи

## Часть 14. Command / Control System (Система команд и управления)

---

# Главная идея

К этому моменту архитектура уже умеет:

```text
Анализировать состояние

Считать экономику

Накапливать знания

Формировать цели

Выбирать стратегию

Запускать операции
```

---

Возникает новая проблема.

---

Если империя полностью автономна:

```text
Как игрок может вмешаться?
```

---

И ещё важнее:

```text
Как вмешаться,
не разрушая архитектуру?
```

---

Именно эту задачу решает Command / Control System.

---

# Главный переход мышления

Ранняя архитектура:

```text
Игрок управляет крипами.
```

---

Более зрелая:

```text
Игрок управляет комнатами.
```

---

Продвинутая:

```text
Игрок управляет операциями.
```

---

Command System:

```text
Игрок управляет намерениями.
```

---

# AUTO и CONTROL

Это основа системы.

---

AUTO отвечает:

```text
Империя работает самостоятельно.
```

---

CONTROL отвечает:

```text
Игрок может изменить поведение.
```

---

Важно понимать.

---

CONTROL не заменяет AUTO.

---

CONTROL корректирует AUTO.

---

# Аналогия

Автопилот самолёта.

---

AUTO:

```text
Самолёт летит самостоятельно.
```

---

CONTROL:

```text
Пилот задаёт ограничения и команды.
```

---

Автопилот остаётся включённым.

---

# Command vs Task

Очень важное различие.

---

Task:

```text
Перенести 300 энергии.
```

---

Command:

```text
Поддерживать комнату любой ценой.
```

---

Task является действием.

---

Command является намерением.

---

# Что такое Command

Команда — это директива игрока.

---

Например:

```js
{
  type: "command";
}
```

---

Команда существует выше операций.

---

# Примеры команд

---

## Запрет

```js
{
    room: "W8N3",

    command: "noUpgrade"
}
```

---

Империя перестаёт улучшать контроллер.

---

## Форсирование

```js
{
    room: "W8N3",

    command: "forceUpgrade"
}
```

---

Приоритет резко повышается.

---

## Заморозка

```js
{
    room: "W8N3",

    command: "freeze"
}
```

---

Развитие останавливается.

---

## Защита

```js
{
    room: "W8N3",

    command: "protect"
}
```

---

Империя начинает усиливать оборону.

---

# Уровни управления

Обычно существует несколько уровней.

---

## Empire Commands

Вся империя.

---

Пример:

```js
{
    scope: "empire",

    command: "economyMode"
}
```

---

## Room Commands

Отдельная комната.

---

Пример:

```js
{
    scope: "room",

    room: "W8N3"
}
```

---

## Operation Commands

Операция.

---

Пример:

```js
{
  operation: "remoteMining";
}
```

---

## Group Commands

Группа объектов.

---

Например:

```text
Все удалённые шахты.
```

---

# Override

Ключевое понятие.

---

Override означает:

```text
Ручное переопределение.
```

---

Например.

---

AUTO говорит:

```text
Снизить апгрейд.
```

---

CONTROL говорит:

```text
Продолжать апгрейд.
```

---

Побеждает:

```text
CONTROL
```

---

# Приоритеты управления

Часто используется такая схема.

---

```text
Player Command
      ↓

Strategy
      ↓

Policy
      ↓

Operations
      ↓

Tasks
```

---

Чем выше уровень — тем выше власть.

---

# Политика разрешений

Очень полезный механизм.

---

Пример:

```js
{
    build: false,

    upgrade: true,

    expand: false
}
```

---

Комната автоматически подчиняется ограничениям.

---

# Directives

Следующий уровень.

---

Команда может быть не приказом, а пожеланием.

---

Например:

```js
{
  directive: "increaseEnergy";
}
```

---

Это не жёсткое требование.

---

Это предпочтение.

---

# Жёсткие и мягкие команды

---

Жёсткая:

```text
Остановить колонизацию.
```

---

Мягкая:

```text
Снизить приоритет колонизации.
```

---

Очень полезное разделение.

---

# Command Lifetime

Команда должна иметь срок действия.

---

Например:

```js
{
  expires: 500000;
}
```

---

Иначе Memory быстро превращается в кладбище старых приказов.

---

# Источник команды

Полезно хранить автора.

---

Например:

```js
{
  source: "player";
}
```

---

или:

```js
{
  source: "system";
}
```

---

# Command Queue

Часто используется очередь команд.

---

Пример:

```js
Memory.commands = [];
```

---

Империя постепенно их обрабатывает.

---

# Command Repository

Более зрелый вариант.

---

```js
Memory.control;
```

---

Содержит все активные директивы.

---

# Пример AUTO/CONTROL

AUTO сообщает:

```text
Комната неэффективна.
```

---

Policy предлагает:

```text
Остановить апгрейд.
```

---

Но игрок создаёт команду:

```js
{
    room: "W8N3",

    command: "forceUpgrade"
}
```

---

И система подчиняется.

---

# Контроль без микроменеджмента

Самая важная цель Command System.

---

Игрок НЕ говорит:

```text
Крип №123 иди сюда.
```

---

Игрок говорит:

```text
Эта комната приоритетна.
```

---

Архитектура сама реализует решение.

---

# Режимы управления

Очень популярная практика.

---

Например:

```text

```

---

```text

```

---

# Почему это важно

Без Command System автономная архитектура часто становится неудобной.

---

Игроку приходится:

```text
Ломать код

Менять константы

Вмешиваться вручную
```

---

Система команд создаёт официальный способ управления.

---

# Главный архитектурный эффект

После появления Command / Control System игрок перестаёт управлять:

```text
Крипами
```

---

И перестаёт управлять:

```text
Задачами
```

---

Он начинает управлять:

```text
Приоритетами

Ограничениями

Намерениями

Целями
```

# Главные выводы

1. Command System является интерфейсом между игроком и империей.

2. Команды работают выше операций и задач.

3. CONTROL не заменяет AUTO, а корректирует его.

4. Игрок управляет намерениями, а не исполнителями.

5. Override позволяет переопределять решения автоматики.

6. Команды должны иметь область действия и срок жизни.

7. Архитектура остаётся автономной даже при ручном вмешательстве.

8. Это естественное место для реализации концепции AUTO / CONTROL.
