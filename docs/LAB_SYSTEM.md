# LAB SYSTEM

Документ описывает фактическое текущее состояние лабораторной системы империи на момент снятия снимка (данные `Memory.rooms[*]` + фактическое содержимое лаб/реакторов/boost-лаб через `Game.getObjectById().store`).

**Все реакции сверены с официальной документацией Screeps:**
`https://docs.screeps.com/resources.html` (раздел "Mineral compounds", таблица формул и бустов).
Никакие сторонние источники (форумы, калькуляторы, вики) не использовались.

Изменений кода/конфигов/памяти в рамках подготовки документа не производилось.

---

## Общая архитектура

В каждой из 5 комнат — 10 лабораторий: 3 производственные тройки (`labs`, `labs2`, `labs3`) + 1 boost-лаба. Один `labWorker` на комнату обслуживает все тройки по очереди (round-robin).

Официальная таблица реакций (только используемые в империи компоненты):

```text
Базовый:  OH   = H + O

Тир 1:    KH   = K + H   → CARRY            KO   = K + O   → RANGED_ATTACK
          LO   = L + O   → HEAL             LH   = L + H   → WORK (build/repair)
          ZO   = Z + O   → MOVE
          UO   = U + O   → WORK (harvest)   UH   = U + H   → ATTACK

Тир 2:    KH2O = KH + OH → CARRY            KHO2 = KO + OH → RANGED_ATTACK
          LHO2 = LO + OH → HEAL
          ZHO2 = ZO + OH → MOVE
          UHO2 = UO + OH → WORK (harvest)   UH2O = UH + OH → ATTACK

Тир 3:    XKH2O  = KH2O + X → CARRY
          XKHO2  = KHO2 + X → RANGED_ATTACK
          XLHO2  = LHO2 + X → HEAL
```

**КРИТИЧЕСКАЯ НАХОДКА.** Два из 15 проверенных конфигов троек указывают `product`, который **не соответствует** официальной реакции для заданной пары `reagent1+reagent2`. Игра всегда производит то, что определено таблицей реакций для физических реагентов в лабах — независимо от того, что записано в поле `product` конфига. Поле `product` в этих двух случаях — просто неверная метка, которая не влияет на реальную химию, но вводит в заблуждение того, кто читает конфиг. Подробности — в разделах по комнатам E35S39 и E37S38 и в отчёте (раздел "Обнаруженные неопределённости").

Все 5 boost-лаб на момент снимка **пусты** (`{}`) — ни один буст не хранится готовым к применению ни в одной комнате.

## Комната E35S37

```text
labs  (LHO2 + X → XLHO2, HEAL тир3 — реакция верна по таблице):
  lab1: LHO2 3000/3000 (полно)
  lab2: X    2965/3000 (почти полно)
  reactor: XLHO2 45 (копится, порог выгрузки MIN_UNLOAD=50 — близко)
  Статус: работает штатно.

labs2 (KHO2 + X → XKHO2, RANGED_ATTACK тир3 — реакция верна по таблице):
  lab1: пусто (нет KHO2!)
  lab2: X 3000/3000 (полно)
  reactor: пусто
  Статус: ПРОСТАИВАЕТ — нет реагента1 (KHO2).
  ВАЖНО: реакция KHO2+X→XKHO2 сама по себе корректна. Но настоящий
  KHO2 (= KO + OH) НЕ производится НИ ОДНОЙ тройкой ни в одной из 5
  комнат империи (см. находку по E35S39 ниже) — простой этой тройки
  не устранить логистикой, нужно сначала наладить производство
  подлинного KHO2 где-то в цепочке.

labs3 (KH2O + X → XKH2O, CARRY тир3 — реакция верна по таблице):
  lab1: KH2O 3000/3000 (полно)
  lab2: X    3000/3000 (полно)
  reactor: XKH2O 25 (копится)
  Статус: работает штатно.

boostLab: пусто.
```

## Комната E35S39

```text
labs (reagent1: KH, reagent2: OH, конфиг заявляет product: "KHO2"):

  ⚠ КРИТИЧЕСКАЯ НАХОДКА (проверено по docs.screeps.com/resources.html):
  Официальная реакция KH + OH даёт KH2O (CARRY, тир2), а НЕ KHO2.
  KHO2 получается только из реакции KO + OH (Keanium Oxide + Hydroxide).
  Конфиг этой тройки физически не может произвести KHO2 — какие бы
  реагенты KH и OH в ней ни находились, лаборатория будет производить
  KH2O, что подтверждается фактическим снимком (см. ниже).

  lab1: KH 20/3000 (ПОЧТИ ПУСТО)
  lab2: OH 2970/3000 (полно)
  reactor: KH2O 15 — это НЕ посторонний/чужой ресурс, как
    предполагалось в предыдущей версии документа, а ТОЧНЫЙ и
    ЕДИНСТВЕННО ВОЗМОЖНЫЙ продукт данной пары реагентов согласно
    официальной таблице реакций. Реактор работает штатно и
    производит именно то, что физически может.

  Статус: реакция идёт корректно с точки зрения игровой механики,
  но результат (KH2O) НЕ ТОТ, что заявлен в конфиге и НЕ ТОТ, что
  нужен E35S37.labs2 (которой нужен настоящий KHO2).

  Вариант исправления (только для рассмотрения Архитектором, не
  выполняется в рамках данного ТЗ): чтобы получить настоящий KHO2,
  либо заменить reagent1 этой тройки с KH на KO (потребует отдельной
  тир1-реакции K+O→KO, которая сейчас нигде не производится), либо
  признать, что эта тройка правильно производит KH2O, и обновить
  метку product в конфиге на "KH2O" (и решить, куда девать KH2O —
  сейчас его напрямую использует E35S37.labs3 как реагент1, так что
  переток может оказаться даже полезным, но это решение архитектурное).

labs2 (O + H → OH, реакция верна по таблице, локально → labs реагент2):
  lab1: O 2980/3000 (полно)
  lab2: H 60/3000 (низкий уровень)
  reactor: OH 15 (копится)
  Статус: работает, но H на грани дефицита.

labs3 (K + H → KH, реакция верна по таблице — CARRY тир1, локально
       → labs реагент1, если considерировать текущий (ошибочный)
       конфиг labs):
  lab1: K 3000/3000 (полно)
  lab2: пусто (нет H!)
  reactor: KH 10 (копится)
  Статус: ПРОСТАИВАЕТ — нет реагента2 (H).

Наблюдение: labs2 и labs3 в этой комнате КОНКУРИРУЮТ за один и тот же
ресурс H (оба берут его как реагент2). Общий H в комнате в дефиците.

boostLab: пусто.
```

## Производственные цепочки

```text
Сырьё (минералы + O/H)
        ↓
Тир1: KH, LO, ZO, KO(отсутствует в производстве!), UO, UH(отсутствует)
        ↓
OH производится локально в КАЖДОЙ из 5 комнат (labs2, за
исключением E35S37, где своей OH-тройки нет — вся OH для E35S37
поступает извне через реагент LHO2/KH2O/KHO2, уже готовыми тир2)
        ↓
Межкомнатная поставка сырья в E35S37:
   E36S38.labs   → LHO2  → E35S37.labs   ⎫ дублируют друг друга —
   E37S37.labs2  → LHO2  → E35S37.labs   ⎭ подтверждённая ошибка
   E35S39.labs   → ЗАЯВЛЕН как KHO2, РЕАЛЬНО производит KH2O
                    → не долетает как KHO2 до E35S37.labs2
   (KH2O из E35S39.labs, если не перенаправляется, физически похож
    на реагент labs3 в E35S37 — но E35S37.labs3.lab1 уже полон
    KH2O 3000/3000 из неустановленного источника — совпадение
    состава требует отдельной проверки Архитектором, не установлено
    в рамках этого ТЗ, поступает ли KH2O из E35S39 фактически в
    E35S37 или это независимые накопления)
        ↓
Тир3 катализация (X) — ТОЛЬКО в E35S37:
   XLHO2  (HEAL)          — работает штатно
   XKHO2  (RANGED_ATTACK) — простаивает, настоящий KHO2 нигде не
                             производится (см. находку по E35S39)
   XKH2O  (CARRY)         — работает штатно
        ↓
Параллельная отдельная ветка — E37S38 (тир2, без катализации X):
   E36S38.labs3 → ZO → E37S38.labs3 → ZHO2 (MOVE)     — верно
   E37S38.labs: реагенты UO+OH → РЕАЛЬНО производят UHO2
                (WORK/harvest), а НЕ UH2O (ATTACK), как заявлено
                в конфиге — см. критическую находку выше
        ↓
Боевые роли (по названиям групп из ТЗ №30, раздел 3):
   HEAL              → Healer (Группа1, Группа2) — обеспечен
   MOVE              → вероятно все роли обеих групп — обеспечен
   RANGED_ATTACK     → роль не указана в составе групп — вопрос,
                        и физически не производится (см. выше)
   CARRY             → роль не указана в составе групп — вопрос
   WORK/harvest(UHO2)→ Miner Energy, Mineral Miner — при исправлении
                        метки конфига E37S38.labs фактически уже
                        близко к готовности (реагенты в принципе
                        подходящие, только не хватает UO и верной
                        метки)
   TOUGH             → НЕ ПРОИЗВОДИТСЯ ВООБЩЕ, ни базовый G, ни любой
                        компонент G-цепочки не встречается ни в одном
                        из 15 конфигов
        ↓
Команда: Группа №1 (Tank, Miner Energy, Healer) — добыча энергии 4000
         Группа №2 (Tank, Mineral Miner, Healer) — добыча минерала O
        ↓
Цель применения: экспансия в соседнюю SK-комнату
```

## Конечные бусты

```text
XLHO2 (HEAL, тир3) — E35S37.labs
  Реакция верна по официальной таблице. Роль: Healer (обе группы).
  Статус: реакция идёт штатно.

XKHO2 (RANGED_ATTACK, тир3) — E35S37.labs2
  Реакция сама по себе верна (KHO2+X→XKHO2), НО реагент KHO2 нигде
  в империи не производится по-настоящему (единственная тройка,
  заявленная как его источник — E35S39.labs — физически производит
  KH2O, не KHO2). Роль не указана в составе групп из ТЗ №30 —
  назначение не определено.
  Статус: простаивает, и не может заработать без изменения
  конфигурации где-то выше по цепочке.

XKH2O (CARRY, тир3) — E35S37.labs3
  Реакция верна. Роль не указана в составе групп из ТЗ №30 —
  назначение не определено.
  Статус: работает штатно.

UHO2 (WORK/harvest, тир2, фактический продукт E37S38.labs, ошибочно
      помеченный в конфиге как "UH2O")
  Реальная химия: UO + OH → UHO2. Потенциально соответствует ролям
  Miner Energy / Mineral Miner.
  Статус: простаивает (нет UO), метка конфига не совпадает с
  реальностью — требует решения Архитектора (см. раздел находок).

ZHO2 (MOVE, тир2) — E37S38.labs3
  Реакция верна. Вероятно, для общего ускорения обеих групп.
  Статус: работает, с локальным затором логистики.

ОТСУТСТВУЕТ ПОЛНОСТЬЮ: TOUGH-буст (цепочка G: GH/GO→GH2O/GHO2→
  XGH2O/XGHO2). Ни один компонент этой цепочки не встречается ни в
  одном из 15 конфигов. Роль "Tank" в обеих группах SK-экспансии по
```

## Применение бустов

```text
Группа №1 (Tank, Miner Energy, Healer) — добыча энергии с источника 4000:
  Healer       → XLHO2 (HEAL) — обеспечен, реакция штатна.
  Tank         → TOUGH-буст ОТСУТСТВУЕТ как класс производства.
  Miner Energy → WORK/harvest-буст (UHO2) потенциально близок к
                 готовности, но простаивает и содержит ошибку метки
                 конфига (см. находку по E37S38.labs).

Группа №2 (Tank, Mineral Miner, Healer) — добыча минерала O:
  Healer         → XLHO2, аналогично Группе №1 — обеспечен.
  Tank           → TOUGH отсутствует, аналогично.
  Mineral Miner  → аналогично Miner Energy.

MOVE (ZHO2) — не привязан явно ни к одной роли в ТЗ, по смыслу
  логично ускоряет обе группы при экспансии в SK-комнату.
```
