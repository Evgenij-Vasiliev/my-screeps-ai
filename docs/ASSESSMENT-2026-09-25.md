## 3. Что стало лучше с 24.09 (закрыто)

1. **Регрессионная защита вернулась под контроль версий.** `tests/` больше не в `.gitignore`,
   в `package.json` появился `"test": "node tests/run-all.js"`, у раннера есть `--list`, `-v`,
   `--timeout`. Это ровно те пункты P0 #3 и P1 #5 прошлой оценки.
2. **Секрет закрыт системно.** `screeps.token.js` — единая точка получения токена
   (`SCREEPS_TOKEN` → `.screeps.json` → `~/.screeps.json`), `Gruntfile.js` больше не хранит токен,
   README описывает процедуру ротации и очистки истории.
3. **Хардкод состояния игры вынесен в `Memory.empire`** (`shard.state.js` + `constants/empire.js`):
   комнаты, ID линков, клетки контейнеров, маршруты, обход обсервера, комнаты риска, точка сбора.
   `ensure()` дозаполняет только отсутствующие ключи — правки владельца не затираются, после
   Global Reset поведение восстанавливается. Порог пре-спавна считается от настроенных маршрутов.
4. **Гейт по `bucket` работает.** `empire.js` при `Game.cpu.bucket < CPU.BUCKET_CRITICAL` пропускает
   `observerManager`, `terminalNetwork`, `marketManager`; ядро (комнаты, оборона, ремоут) работает
   всегда. Пункт 10 аудита закрыт содержательно, а не формально.
5. **Монолиты разобраны.** `constants.js` 1921 → barrel без значений, значения в `constants/*.js`
   (11 доменов, ~2 000 строк); `market.manager.js` 1254 → `market.core/sell/buy/labImport`.
   Идентичность объектов конфига и состав экспортов закреплены `tests/module.barrel.test.js`.
6. **Изоляция сбоев в коде, а не в комментариях.** `empire.js` оборачивает каждую подсистему,
   `room.manager.js` — каждую комнату и группу логики через `safe(label, fn)`. Падение одной
   комнаты не роняет тик.
7. **Новый слой деплоя спроектирован правильно.** `scripts/deploy.modules.js` решает реальную
   проблему движка (require на шарде игнорирует `./` и не разрешает соседей по папке), проверяется
   офлайн `tests/deploy.modules.test.js` (**28/28 PASS**), не тянет grunt/screeps-api и падает
   ДО обращения к API, если `require` не разрешается по правилам движка.

## 4. Новые дефекты и регрессы (по приоритету)

### P0 — утёкший секрет и потеря работы

1. **Незакоммиченная работа снова существует в одном экземпляре.** В рабочем дереве —
   `scripts/deploy.modules.js` (11 875 байт) и `tests/deploy.modules.test.js` (untracked), плюс
   правки `Gruntfile.js` и `tests/live.diff.deployed.js`. Это **весь новый путь деплоя**:
   `git checkout .` / `git clean -fd` уничтожат и логику резолва модулей, и её тест. В прошлой
   оценке это был пункт P0 #2 — он воспроизвёлся через сутки в новом месте.

### P1 — сломанные гейты и противоречия в конфиге

2. **`tsc`-гейт сломан: exit 0 → exit 2.** Все 20 ошибок в `scripts/` (это Node-файлы, README о них
   предупреждает), но среди них **две настоящие типовые ошибки** —
   `scripts/deploy.modules.js(244,3)` и `(258,3)`: `Type '{}' is not assignable to type
   'Record<string, string>'`. README утверждает «`tsc` ругается только на Node-файлы», прошлая оценка
   писала «exit 0». Формально модули бота чисты, но **гейт «tsc чист» больше не выполняется**:
   CI, который просто зовёт `tsc --noEmit`, будет красным всегда и перестанет ловить реальные ошибки.
   Лечится либо `@types/node` + `"types": ["screeps","node"]`, либо исключением `scripts/` из
   `jsconfig.json` и отдельным tsconfig для инструментов.
3. **Фабричный контур: три источника противоречат друг другу.**
   - `constants/tasks.js:24-45`: комментарий «Фабричный контур **включён** (решение владельца)… Все три
     флага включаются и выключаются только вместе», а значения — `fillFactoryEnergy: false`,
     `collectFactoryBattery: false`, `factory: false`;
   - `tests/factory.manager.test.js` требует «все три включены» → **единственный красный тест**;
   - `docs/SESSION_HANDOFF.md` §0.000 называет это «решением владельца по фабричному контуру».
   При этом коммит `9140f31` **перевернул значения `true → false`** (`git show 9140f31^:constants.js`
   → `factory: true`), а тот же коммит содержит разбор «гейт склада убран, фабрики варят, +120 000 кр
   за окно». То есть в репозитории одновременно лежат «фабрики работают» (док) и «фабрики выключены»
   (конфиг). Нужно одно явное решение: либо вернуть `true` и сделать тест зелёным, либо признать
   выключение осознанным и переписать комментарий, тест и доки. Сейчас красный тест маскирует
   будущие реальные поломки.
4. **Дрейф чисел в документах (снова).** README: «31 PASS / 1 FAIL (32 файла)» — факт **32 PASS /
   1 FAIL (33 файла)**. `SESSION_HANDOFF.md` §0.00: «30 PASS / 0 FAIL». Прошлая оценка отмечала этот
   класс дефекта; он воспроизвёлся на следующий день, потому что числа в доки пишутся руками.

6. ✅ **ИСПРАВЛЕНО 2026-09-25 (задача 10).** `console.log` в проде вырос: 60 → 68; в горячих

### P3 — процесс и документация

9. **Нет CI и хуков.** `package.json` знает только `test`; нет `lint`/`typecheck`/`deploy:check`.
   Ни `.github`, ни pre-commit. Все три гейта («тесты зелёные», «eslint без ошибок», «tsc чист»)
   держатся на памяти человека — поэтому п. 2–4 и появились.
10. **`SESSION_HANDOFF.md` по-прежнему содержит `## 7. Как проверять` дважды** (строки 346 и 362) —
    пункт 12 прошлой оценки не закрыт.
11. **Trunk не определён.** Локально 4 ветки (`main`, `Новая-Империя`, `empire-candidate-1/2`) плюс
    remote, работа идёт на `Новая-Империя`, деплой — в ветку `test` шарда. Что считается основной
    линией, из репозитория не следует.

## 6. Вердикт

Архитектура здорова и выдержала рост до **16.2k строк кода + 18k строк тестов**: тонкое ядро,
изоляция сбоев по комнатам, конфиг с контракт-тестом, Task System без «божественного объекта»,
живые замеры в документации вместо лозунгов. За сутки закрыты почти все P0/P1 прошлой оценки —
это сильный темп.

Но проект **повторяет один и тот же класс ошибок**: работа живёт вне git, числовые утверждения в
доках расходятся с фактом, а гейты качества (тесты/eslint/tsc) не автоматизированы. Сегодня это
дало красный тест и сломанный `tsc` при формально чистом коде бота. Первые пять пунктов плана
стоят **меньше двух часов** и возвращают все три гейта в зелёное состояние; содержательный долг
остаётся один — **бюджет CPU** (13.56 из 20 мс/тик, пики блоков >13) и его свежий замер.

Итог: **7.5 / 10**, с потенциалом 8.5+ сразу после закрытия пунктов 1–4 — без единой правки
архитектуры.
