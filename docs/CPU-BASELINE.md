## 3. Стоимость игровых API (замерено, не оценка)

| API | CPU за вызов |
|---|---|
| `Game.cpu.getUsed()` | **0.000244** |
| `Game.getObjectById(id)` | **0.000152** |
| `room.find(FIND_STRUCTURES)` — первый в тике | 0.007 (304 структуры) |
| `room.find(FIND_STRUCTURES)` — повторный (кэш движка) | **0.0041** |

### ⚠️ Поправка к оценке №1: `cpuMonitor.trackRole` на каждого крипа

Замерено: `getUsed()` стоит **0.000244 CPU**. Два вызова на крипа = 0.0005 CPU.
При 31 крипе это **≈0.015 CPU/тик**, при 100 крипах — **≈0.05 CPU/тик**.

**Оценка в `CPU-OPTIMIZATION-ASSESSMENT.md` (0.2–0.8 CPU/тик) завышена примерно в 10–40 раз.**
Реальная цена — аллокация замыкания и вызов функции, а не `getUsed()`.
Приоритет находки 2.2 следует понизить с **P0 до P3**.

### Подтверждено замером

- `Object.values(Game.creeps)` — 0.0035 CPU **за каждый вызов**. В `role.builder.js:22`
  он вызывается на каждого строителя, в `creep.factory.js:31` — `_.some(Game.creeps, …)`
  на каждую свободную точку майнера. При 10 строителях это ≈0.035 CPU/тик только на аллокации.
- `room.find` **кэшируется движком** в пределах тика (повтор в 1.7 раза дешевле первого).
  Значит, рекомендация плана «использовать `room.find(FIND_HOSTILE_CREEPS)` вместо обхода
  списка id» верна: первый вызов дешёвый, а JS-обход 300–500 объектов дороже.

## 4. Стоимость рынка (главная гипотеза — подтверждена)

| Запрос | CPU |
|---|---|
| `getAllOrders({ORDER_BUY, ENERGY})` — первый в тике | **0.824** |
| тот же запрос повторно в том же тике (кэш движка) | 0.094 |
| `getAllOrders({ORDER_BUY, UTRIUM})` | **0.164** |
| `getAllOrders({ORDER_SELL, ENERGY})` | **0.893** |
| Ордеров BUY по энергии | 359 |
| Своих ордеров | 0 |
| Терминалов в Империи | 5 |
| Кредиты | 1 453 520 534 |

**Вывод:** вызов дорогой (0.16–0.89 CPU), но движок кэширует результат по паре
(тип, ресурс) в пределах тика. Реальная цена `market.manager.js` = **(число различных пар
«тип+ресурс» за тик) × 0.16–0.9 CPU**. При 5 терминалах и нескольких избыточных ресурсах
это **1–4 CPU/тик**, то есть **12–45 % всего расхода**.

**Поправка к оценке:** в `CPU-OPTIMIZATION-ASSESSMENT.md` указано «2–8 CPU/тик» — верхняя
граница завышена; реалистичный диапазон **1–4 CPU/тик**. Находка остаётся **P0 №1**.

## 5. Разбор Memory: 162 КБ, из них ~32 КБ — мусор

| Секция | Байт | Доля |
|---|---|---|
| `rooms` | **85 900** | **53 %** |
| `creeps` | 6 318 | 4 % |
| `towerState` | 785 | 0.5 % |
| `empire`, `labs`, `spawns`, `market`, `remoteRooms` | ~780 | 0.5 % |
| **отладочные `__*` поля** | **~32 000** | **~20 %** |

В `Memory` накопились десятки мёртвых отладочных полей от прошлых сессий:
`__dump` (9 010), `__probe1` (4 432), `__st3` (2 109), `__s` (1 936), `__lvA` (1 772),
`__g` (1 691), `__lsnap` (1 496), `__pS1` (1 326), `__st1` (1 079), `__react` (992),
`__w` (762), `__lvG` (728), `__p3` (694), `__xDeal` (289), `__agg`, `__c`, `__boost`,
`__boostMetric`, `__alive`, `__pS2`, `__pX`, `__q`, `__s1`, `__s2`, `__lvB`, `__lvD`,
`__lvE`, `__lvF` и др.

**Это самая дешёвая победа из всех найденных:** удаление мёртвых `__*` полей сжимает
Memory примерно на 20 % без единой строки изменений в логике. Правку не выполнял —
удаление полей из боевой Memory не входит в Шаг 0 и требует вашего подтверждения
(часть имён может использоваться).

Прочее по Memory:
- `rooms` = 85.9 КБ — подтверждает находку 2.13 (`structureCache` с массивами id стен/валов/дорог
  в `Memory`). Это по-прежнему **P0 №2**.
- `creeps` = 6 318 байт; **9 из 31 крипа несут копию задачи** (`memory.task`) — подтверждает
  находку 2.9. Размер одной задачи ~100–130 байт, то есть ≈1 КБ из 6.3 КБ — дубль очереди.
- `towerState` = 785 байт — подтверждает находку 2.8.

## 6. Технические заметки по замерам

1. **Консольная команда длиннее ~1024 символов молча отбрасывается** (проверено: 1000 символов
   выполняется, 1200 — нет, ответ всё равно `ok`). Все выражения в `scripts/baseline.js`
   держатся короче лимита, а `evalInGame` падает с явной ошибкой, если выражение длиннее.
2. Результат выражения консоли не возвращается через POST — скрипт пишет его во временное
   поле `Memory.__bench_*` и читает через `memory.get`, после чего удаляет.
3. `Game.cpu.getUsed` **нельзя отрывать от объекта** (`const u = Game.cpu.getUsed; u()` →
   `Illegal invocation`) — оборачивается в стрелку.
4. Консоль изредка теряет команду — в `evalInGame` добавлены 3 попытки.
5. Аккаунт играет на **shard3** (не shard0): `cpuShard: {shard3: 20}`.
