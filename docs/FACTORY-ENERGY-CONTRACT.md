# Фабричный контур: условия запуска и план подготовки (25.09.2026)

## 0. Решение

**Фабрики включены флагами, но фактически ими управляет гейт резервов.**
Три флага (`fillFactoryEnergy: true`, `collectFactoryBattery: true`,
`factory: true`) подняты; тест держит инвариант «три флага совпадают»
(`tests/factory.manager.test.js`, раздел 1), а расход энергии закрыт
`factory.manager.canTakeStorageEnergy`. Пока гейт закрыт, фабрика энергии не
получает и не выедает излишек склада, которым живут терминал (комиссии рынка и
терминал-сети), лаборатории и PowerSpawn.

**Условие открытия гейта — по каждой комнате, оба одновременно:**

| Резерв | Значение | Кто защищает |
|---|---|---|
| Терминал | **100 000 … 150 000** | `factory.manager.canTakeStorageEnergy` (снабжение фабрики гейтится по терминалу) |
| Склад | **≥ 150 000**, а для фабрики > `150 000 × 1.1 = 165 000` | `energySource.withdrawFromStorage` (жёсткий пол) + рабочий буфер |

Пока условие не выполнено хотя бы по одной комнате, снабжение фабрики в ней не
запускается. Ниже — что мешало, что уже сделано и что осталось.

## 1. Что мешало терминалу держать 100 000

Терминал пополняется **только** из излишка склада, а прежний порог подвоза был
`STORAGE.ENERGY_MIN × 1.3 = 195 000`. Живой склад при этом держится на
**191–195k** (замеры 25.09.2026, `shard3`), то есть порог был выше склада и
подвоз не включался вообще. Следствие — терминалы стояли на **39–71k** и до цели
100 000 не доходили никогда (это же записано в `constants/logistics.js`).

Это и была настоящая причина «фабрика ложит терминал»: фабрика, забравшая
излишек 150–195k, окончательно запирала подвоз. Прямого `withdraw` из терминала у
фабрики нет и не было (`energySource.withdrawFromStorage` берёт только Storage).

## 2. Что уже сделано (подготовка условий)

1. **Порог подвоза терминала понижен до резерва склада.**
   Новый `TERMINAL_SUPPLY.FILL_STORAGE_MULTIPLIER = 1.0` (150 000) вместо 1.3
   (195 000). Теперь терминал реально доходит до `ENERGY_TARGET` (100 000).
   Прежний множитель 1.3 остался только у `STORAGE_RESERVE_MULTIPLIER` — как
   порог **донора** для `terminalNetwork.balanceEnergy`.
   Генератор (`task.generators.js`) и исполнитель (`task.executors.js`)
   проверяют один и тот же новый порог.

2. **Жёсткий пол склада.** `energySource.withdrawFromStorage` обрезает забор по
   остатку сверх резерва: `amount = min(рюкзак, storageEnergy − 150 000)`. Раньше
   проверялся только факт «резерв ещё цел», и один воркер при складе 150 001
   оставлял 149 701. Теперь склад не уходит ниже 150 000 ни на единицу, сколько
   бы воркеров ни забирало в тике. Аварийный режим (`ignoreReserve`) пол
   игнорирует осознанно.

3. **Гейт фабрики готов заранее** — `factory.manager.canTakeStorageEnergy`:
   снабжение берёт энергию только при `склад > 165 000` **И**
   `терминал ≥ 100 000`. Проверяют и генератор, и исполнитель (для уже стоящих
   в очереди задач). Буфер 15k над резервом (`FACTORY.ENERGY_RESERVE_MULTIPLIER
   = 1.1`) оставлен специально: лаборатории, PowerSpawn и ремонт берут из склада
   только выше `STORAGE.ENERGY_MIN` (`lab.worker.js`), и фабрика не имеет права
   их объедать.

Итог: флаги уже подняты, а гейт сам решает, когда фабрика получает энергию, —
менять код для включения/выключения больше не нужно.

## 4. Что осталось, чтобы условия выполнились во всех комнатах

Дефицит двух комнат — **26 757 энергии суммарно**. Способы:

- **Купить энергию на рынке** (рекомендуется). `MARKET.BUY_RESOURCES` энергию не
  содержит, поэтому это либо разовая сделка из консоли
  (`Game.market.deal`), либо небольшая правка закупочного контура. Цена мала:
  империя зарабатывает ≈5 170 кр/тик.
- **Поднять доход/сократить стоки** — единственный способ, при котором инвариант
  держится сам, без разовых вливаний.
- **Межкомнатная переброска**: у трёх «богатых» комнат суммарный излишек
  ≈41k — этого хватает на 27k дефицита, но энергия лежит в Storage, а `send`
  работает из Terminal, поэтому нужен отдельный шаг storage→terminal→send.

Корневая причина дефицита — не пороги, а энергобаланс: суммарно по империи
запас 1 264 656 энергии против 1 250 000 требуемых, то есть запас всего +1.2 %.
Пороги можно выставить идеально, но разрыв в производстве это не закроет.

Разовая помощь из консоли (аккуратно, комиссия списывается энергией терминала,
поэтому покупаем с запасом; `ORDER_SELL` — чужие заявки на продажу):

```js
// Добрать энергию в терминал комнаты до цели. Пример для E35S39.
const room = "E35S39";
const term = Game.rooms[room].terminal;
const need = 13000; // больше дефицита: часть уйдёт на комиссию
const order = Game.market
  .getAllOrders({ type: ORDER_SELL, resourceType: RESOURCE_ENERGY })
  .filter(o => o.remainingAmount >= need)
  .sort((a, b) => a.price - b.price)[0];
if (order) {
  const cost = Game.market.calcTransactionCost(need, room, order.roomName);
  console.log("fee", cost, "price", order.price * need);
  Game.market.deal(order.id, need, room);
}
```

## 5. Порядок действий (флаги уже подняты)

1. Прогнать `node tests/live.factory.budget.check.js` и убедиться, что в нужных
   комнатах `store` показывает `gate: ОТКРЫТ` (терминал ≥100 000, склад
   >165 000) и держится так хотя бы несколько десятков тиков.
2. Три флага (`fillFactoryEnergy`, `collectFactoryBattery`, `factory`) уже стоят
   `true` вместе; при любом изменении решения двигать их **только вместе** —
   инвариант держит `tests/factory.manager.test.js`.
3. После деплоя снова прогнать тот же скрипт: в комнатах с открытым гейтом
   должны появиться задачи `fillFactoryEnergy`, в остальных — нет.
4. Если терминал просел ниже 100 000 — снабжение выключится само; это нормальная
   работа контракта, а не сбой.

## 6. Границы решения

- Жёстко гарантируется: склад **никогда** ниже 150 000 (пол в `energySource`);
  фабрика **никогда** не берёт энергию при складе ≤165 000 или терминале
  <100 000.
- Не гарантируется: терминал ≥100 000 сам по себе. Это следствие энергобаланса
  комнаты, а не порога. В двух комнатах его не хватает (см. §3–4).
- Вне фабричного контура терминал по-прежнему имеет право уйти ниже 100 000:
  `terminalNetwork` и рынок платят комиссии с полом `ENERGY_MIN` = 10 000.
  Поднять этот пол до 100 000 «в лоб» нельзя — энергия терминалов 39–73k, и
  тогда сеть и рынок встанут целиком (именно поэтому пол уже понижали).
