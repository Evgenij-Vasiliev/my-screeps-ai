# ТЗ №8 — Task System v3.0 — Создание базового каркаса Feature Switches

## 1. Цель

Создать первый рабочий компонент Task System v3.0 — систему централизованных рубильников управления Feature Switches.

Цель этапа:

Подготовить инфраструктуру управления включением и отключением компонентов Империи без изменения кода в будущем.

На данном этапе Feature Switches являются только управляющей инфраструктурой.

Они НЕ должны изменять поведение существующих подсистем.

---

# 2. Архитектурная основа

Использовать документы:

- Task System v3.0 Architecture Specification
- Task System v3.0 Data Model Specification
- Task System v3.0 Component Interface Specification
- Task System v3.0 Roadmap Migration
- TACTIC_GUIDE.md

Раздел:

```
Roadmap Migration
Этап 1 — Feature Switches
```

---

# 3. Ограничения

Обязательно:

- не изменять Task System v2.0;
- не изменять существующие роли крипов;
- не изменять менеджеры Империи;
- не добавлять новые системы управления;
- не создавать отдельные рубильники вне Task System v3.0.

---

# 4. Задача

Создать компонент:

```
featureSwitches
```

расположенный внутри:

```
Memory.taskSystem.switches
```

---

# 5. Требования к структуре данных

Создать базовую структуру:

```
Memory.taskSystem.switches
```

с поддержкой уровней управления:

```
empire

rooms

roles

groups

managers

tasks

creeps
```

Каждый элемент должен иметь единый формат состояния.

Минимально необходимая информация:

```
enabled
reason
updated
```

---

# 6. Требования к логике

Компонент должен обеспечивать:

## Проверку состояния

Возможность получить:

- включен ли объект;
- отключен ли объект;
- причину отключения;
- время последнего изменения.

---

## Изменение состояния

Возможность:

- включить;
- отключить;
- изменить причину;
- обновить время изменения.

---

# 7. Требования к интерфейсу

Создать минимальный интерфейс управления.

Пример требований:

```
enable()
disable()
isEnabled()
getStatus()
```

Названия функций могут быть изменены Тактиком при условии сохранения архитектурного смысла.

---

# 8. Интеграция

На данном этапе:

Feature Switches НЕ подключаются к:

- Dispatcher;
- Scheduler;
- ролям;
- менеджерам;
- задачам.

Только создаётся инфраструктура хранения и управления.

---

# 9. Диагностика

Добавить возможность получить текущее состояние Feature Switches через существующую систему диагностики, если это возможно без изменения архитектуры.

Минимально:

- количество созданных переключателей;
- количество отключенных компонентов.

---

# 10. Проверка выполнения

После выполнения ТЗ должно быть возможно:

1. Создать переключатель.

2. Отключить его.

3. Получить статус.

4. Включить обратно.

5. Увидеть изменения в Memory.

---

# 11. Критерии завершения

ТЗ считается выполненным если:

- создана структура Memory.taskSystem.switches;
- реализовано управление состоянием;
- отсутствуют изменения существующих рабочих систем;
- компонент соответствует архитектуре Task System v3.0;
- предоставлен отчёт Тактика.
