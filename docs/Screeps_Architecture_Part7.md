# Screeps — Архитектура зрелой империи

## Часть 7. Resource Flow System (Система потоков ресурсов)

---

# Главная идея

Большинство игроков видят Screeps так:

```text id="r1a7k5"
Miner
Hauler
Storage
Spawn
```

То есть как набор объектов и крипов.

---

Зрелая архитектура смотрит иначе.

Она видит:

```text id="v3m9q2"
Потоки ресурсов
```

---

Не:

```text id="w8n4c1"
Кто несёт энергию?
```

А:

```text id="x5r2m7"
Куда течёт энергия?
```

---

# Главный переход мышления

Старая модель:

```text id="u7p3k9"
Крипы перемещают ресурсы
```

---

Новая модель:

```text id="z2m8r4"
Ресурсы движутся по сети
```

---

Крипы являются всего лишь транспортом.

---

# Комната как производственная цепочка

Любая комната может быть представлена в виде потока.

---

Простейшая схема:

```text id="a6n1v8"
Source
   ↓
Container
   ↓
Storage
   ↓
Spawn
```

---

Более зрелая схема:

```text id="c9m4q7"
Source
   ↓
Container
   ↓
Storage
   ↓
Terminal
   ↓
Factory
   ↓
Labs
```

---

# Узлы сети

Каждый объект становится узлом.

---

Пример:

```text id="f3k8n2"
Source
Container
Storage
Terminal
Factory
Lab
Spawn
Tower
```

---

Для системы они одинаковы.

---

Каждый узел обладает ресурсами.

---

# Supply и Demand

Основа всей системы.

---

Каждый узел публикует:

```text id="m5r7q1"
Supply
или
Demand
```

---

Supply означает:

```text id="p8n3v6"
У меня есть избыток.
```

---

Demand означает:

```text id="u2k9r5"
Мне нужен ресурс.
```

---

# Пример Supply

Storage:

```js id="g4m1t8"
{
  energy: +500000;
}
```

---

Это означает:

```text id="r7v2k4"
Готов отдать энергию.
```

---

# Пример Demand

Spawn:

```js id="q9n5m3"
{
  energy: -300;
}
```

---

Это означает:

```text id="t4k8r1"
Требуется энергия.
```

---

# Рождение потока

Когда система видит:

```text id="x1m7q9"
Supply
+
Demand
```

возникает поток.

---

Например:

```text id="n6r4v2"
Storage → Spawn
```

---

или:

```text id="j3m8k7"
Terminal → Factory
```

---

# Flow

Поток обычно описывается отдельным объектом.

---

Пример:

```js id="w5n2q8"
{
    resource: RESOURCE_ENERGY,

    source: storage.id,

    target: spawn.id,

    amount: 300
}
```

---

# Поток не является задачей

Очень важный принцип.

---

Плохо:

```text id="s8r4m1"
Flow = Task
```

---

Хорошо:

```text id="k2v7n5"
Flow создаёт задачи
```

---

Иерархия:

```text id="h9m3q6"
Flow
    ↓
Tasks
    ↓
Creeps
```

---

# Почему это важно

Поток может существовать тысячи тиков.

---

Например:

```text id="p4n8r2"
Storage → Spawn
```

---

Пока существует Spawn, поток остаётся.

---

Задачи постоянно появляются и исчезают.

---

# Логистика как сеть

Следующий уровень.

---

Вместо:

```text id="t7k1m5"
Storage → Spawn
```

появляется:

```text id="v8r3q4"
Resource Network
```

---

Схема:

```text id="f2n9k7"
Storage

├─ Spawn
├─ Tower
├─ Terminal
└─ Factory
```

---

Каждый объект становится частью общей сети.

---

# Приоритеты потоков

Не все потоки одинаково важны.

---

Например:

```text id="r5m8n1"
Spawn
```

важнее чем:

```text id="k7q2v4"
Lab
```

---

Поэтому поток получает приоритет.

---

Пример:

```js id="m1r7n9"
{
  priority: 100;
}
```

---

Шкала:

```text id="v4k8q3"
100 = критично
80  = очень важно
60  = важно
40  = обычный поток
20  = низкий приоритет
```

---

# Источник и потребитель

Каждый поток содержит:

```text id="n2m6r8"
Source
Target
Resource
Amount
Priority
```

---

Пример:

```js id="q7v3k5"
{
    source: storage.id,

    target: tower.id,

    resource: RESOURCE_ENERGY,

    amount: 1000,

    priority: 100
}
```

---

# Анализ сети

Система постоянно ищет:

```text id="u5n8m4"

Недостатки
```

---

Например:

```text id="p1k7r3"

```

---

```text id="w6m2q9"

```

---

Результат:

```text id="c4v8n1"

```

# Терминалы как межкомнатные узлы

---

```text id="v9m4q1"

      ↓

Terminal B
```

---

---

Пример:


Очень сильная концепция.

---

Например:

```text id="u1m5q7"

```

---

```text id="p9r4k3"

```

# Архитектурный эффект

После внедрения Resource Flow System игрок перестаёт видеть:

```text id="m2q7v4"
Harvester
Hauler
Builder
```

---

Он начинает видеть:

```text id="r8n1k6"
Источники ресурсов
Потребителей ресурсов
Потоки ресурсов
```

---

Это полностью меняет взгляд на игру.

---

# Главные выводы

1. Основным объектом управления становятся потоки ресурсов.

2. Каждый объект является узлом сети.

3. Каждый узел публикует Supply или Demand.

4. Потоки возникают автоматически из избытков и дефицитов.

5. Потоки создают задачи.

6. Задачи назначаются крипам.

7. Терминалы расширяют сеть до уровня империи.

8. Логистика превращается в балансировку сети ресурсов.
