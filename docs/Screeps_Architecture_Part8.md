# Screeps — Архитектура зрелой империи

## Часть 8. Logistics Network System (Логистическая сеть)

---

# Главная идея

После появления Resource Flow System возникает новый вопрос:

```text id="a1k7m3"
Кто именно будет перемещать ресурсы?
```

Или ещё важнее:

```text id="b4n8q2"
Как эффективно перемещать ресурсы по всей империи?
```

---

Resource Flow System отвечает:

```text id="c7m2r9"
Что должно двигаться.
```

---

Logistics Network System отвечает:

```text id="d3q8v1"
Как это должно двигаться.
```

---

# Разделение ответственности

Очень важный принцип.

---

Resource Flow:

```text id="e6n4k7"
Storage → Spawn
300 энергии
```

---

Logistics Network:

```text id="f9m1q5"
Какой перевозчик?
Каким маршрутом?
Когда?
```

---

# Главный переход мышления

Новичок видит:

```text id="g2r7n4"
Hauler
```

---

Зрелая архитектура видит:

```text id="h5q1m8"
Транспортную сеть
```

---

Крипы становятся аналогом:

```text id="i8n4v2"
Грузовиков
Поездов
Курьеров
```

---

# Базовая модель

Любая логистика состоит из трёх элементов.

---

```text id="j1m9r6"
Источник
↓
Транспорт
↓
Потребитель
```

---

Например:

```text id="k4q2n7"
Storage
↓
Hauler
↓
Spawn
```

---

# Сеть вместо маршрута

На раннем этапе:

```text id="l7n5m3"
Storage → Spawn
```

---

На зрелом этапе:

```text id="m2r8q1"
Storage

├─ Spawn
├─ Tower
├─ Lab
├─ Factory
└─ Terminal
```

---

Появляется сеть получателей.

---

# Узлы сети

Каждый объект становится узлом.

---

Пример:

```text id="n5q1v4"
Storage
Terminal
Container
Factory
Lab
Spawn
Tower
```

---

Узел может одновременно:

```text id="o8m3r7"
Получать ресурсы
Отдавать ресурсы
```

---

# Рёбра сети

Связь между узлами называется ребром.

---

Например:

```text id="p1n6q9"
Storage → Spawn
```

---

или:

```text id="q4m8r2"
Terminal → Factory
```

---

# Вес маршрута

Каждый маршрут имеет стоимость.

---

Например:

```text id="r7q2n5"
Дистанция = 15 клеток
```

---

или:

```text id="s3m9v1"
Дистанция = 60 клеток
```

---

Система предпочитает дешёвые маршруты.

---

# Стоимость доставки

Зрелые архитектуры считают стоимость.

---

Пример:

```text id="t6n4q8"
100 энергии
на 5 клеток
```

---

дешевле чем:

```text id="u2m7r3"
100 энергии
на 50 клеток
```

---

# Логистика как задача оптимизации

Основной вопрос сети:

```text id="v5q1n6"
Как удовлетворить все потребности
с минимальными затратами?
```

---

# Источники запросов

Потребители публикуют запросы.

---

Например:

```js id="w8m4r2"
{
    target: spawn.id,
    resource: RESOURCE_ENERGY,
    amount: 300
}
```

---

Или:

```js id="x1n7q5"
{
    target: tower.id,
    resource: RESOURCE_ENERGY,
    amount: 800
}
```

---

# Агрегация запросов

Сеть объединяет похожие запросы.

---

Вместо:

```text id="y4m9r8"
Spawn 100
Spawn 100
Spawn 100
```

---

Получаем:

```text id="z7q2n1"
Spawn 300
```

---

# Транспортные задания

Логистическая сеть создаёт задания.

---

Например:

```js id="a2m6r4"
{
    pickup: storage.id,

    dropoff: spawn.id,

    amount: 300
}
```

---

```text id="d1n4q6"

```

Критерии выбора:


Простейшая архитектура:


---

Между комнатами.

---

Следующий уровень.

```text id="l8q4n2"
      ↓
```

# Балансировка сети

Система постоянно ищет дисбаланс.

---

Например:

```text id="m1n7q5"
Комната A = 600000 энергии
```

---

```text id="n4m2r8"
Комната B = 5000 энергии
```

---

Создаётся поток:

```text id="o7q5n1"
A → B
```

---

# Резервы

Зрелые системы не расходуют всё.

---

Пример:

```js id="p3m8r6"
{
  reserve: 100000;
}
```

---

Storage не отдаёт запас ниже установленного уровня.

---

# Прогнозирование

Логистика начинает смотреть вперёд.

---

Например:

```text id="q6n1q4"

```

---

или:

```text id="r9m4r7"

```

---

Потоки создаются заранее.

---

# Главный архитектурный эффект

После появления Logistics Network System игрок перестаёт видеть:

```text id="y3m8r6"
Перевозчиков
```

---

Он начинает видеть:

```text id="z6n1q4"
Сеть доставки ресурсов
```

---

Точно так же, как пользователь интернета не думает о конкретном кабеле или маршрутизаторе.

Он думает о сети.

---

# Главные выводы

1. Logistics Network отвечает за перемещение ресурсов.

2. Потоки определяют потребность в перевозке.

3. Узлы образуют транспортную сеть.

4. Перевозчики становятся исполнителями сети.

5. Сеть самостоятельно выбирает маршруты.

6. Сеть балансирует ресурсы между комнатами.

7. Сеть умеет прогнозировать будущие потребности.

8. Логистика становится задачей оптимизации, а не управлением отдельными крипами.
