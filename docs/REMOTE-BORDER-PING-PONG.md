# Отчёт: «крипы дальней добычи не могут перейти границу комнат» (пинг-понг на кромке)

- Дата: 2026-09-18
- Ветка: `Новая-Империя`, HEAD `95d1af0` (+ незакоммиченные правки `traveler.js`)
- Симптом: дальние крипы маршрута `E35S37 → E35S38` (южная удалённая комната)
  бесконечно ходят туда-обратно через границу и никогда не доходят до работы.
- Область правки: **`remote.miner.js`, `remote.hauler.js`, `remote.reserver.js`**
  (+ `types.d.ts` — новое поле `controllerPos`).
- Итог: причина не в Traveler и не в террейне, а в том, что **роль подменяла
  цель рейса центром комнаты** `(25,25)` при каждом выходе крипа из целевой
  комнаты. Путь к источнику в E35S38 дешевле не внутри комнаты, а через дороги
  домашней комнаты, поэтому «дешёвый» маршрут регулярно выводил крипа из
  комнаты — и роль тут же разворачивала его назад, к центру. Круг замыкался.

---

## 1. Живые данные (shard3)

Покадровое наблюдение за комнатами (только чтение, `roomObjects`), интервал ~2 с:

```text
# 0 E35S37 remoteHauler_E35S37@43,7  | E35S38 remoteMiner_E35S37@23,1 | E35S38 remoteHauler_E35S37@22,1
# 2 E35S37 remoteMiner_E35S37@24,49  | E35S37 remoteHauler_E35S37@23,49 | E35S37 remoteHauler_E35S37@44,8
# 4 E35S37 remoteHauler_E35S37@44,8  | E35S38 remoteMiner_E35S37@24,0 | E35S38 remoteHauler_E35S37@23,0
# 9 ... remoteMiner@24,49            | remoteHauler@47,11          | E35S38 remoteHauler@23,0
#12 E35S37 remoteHauler_E35S37@23,49 | E35S38 remoteMiner_E35S37@23,1
#16 E35S37 remoteMiner_E35S37@24,49  | E35S38 remoteHauler_E35S37@22,1
```

Два крипа маршрута `E35S38` (юг) постоянно находятся на кромке: `y=49` в
домашней комнате и `y=0` в удалённой, то есть **каждый 1–3 тика переходят
границу в обе стороны**. Третий крип этого маршрута (`reserver`) работает —
он стоит у контроллера `(19,39)` и резервирует. Крип маршрута `E36S37` (восток)
тоже работает: его источник стоит сразу за западной границей комнаты.

Память крипов в тот же момент:

```text
remoteMiner  pos E35S38:23,1  dest 25,25,E35S38  path 27   srcId=— contId=—
remoteHauler pos E35S38:22,1  dest 36,32,E35S38  path 46   (36,32 — источник)
```

Обратите внимание: **в E35S38 нет контейнера вообще** (в снимке `roomObjects`
только источник `36,32`, контроллер `19,39`, минерал `24,20` и два крипа) —
майнер не мог ни дойти до источника, ни поставить площадку контейнера, а
хайлеру нечего было собирать.

## 2. Почему путь ведёт из комнаты

Террейн и структуры комнат сняты через API (только чтение) и прогнаны
Dijkstra со стоимостью как в PathFinder: стена — нельзя, равнина 2, болото 10,
дорога 1 (`addStructuresToMatrix` Traveler'а).

```text
=== из (24,1) E35S38 к источнику (36,32) E35S38, range 1
    стоимость 80, клеток 45
    первые шаги: E35S38:24,1 -> E35S38:25,0 -> E35S37:26,49 -> E35S37:27,48 -> ...
    комнаты по маршруту: E35S38, E35S37          <-- выход в домашнюю комнату!
    финиш: E35S38:38,31 -> E35S38:37,32

=== тот же маршрут БЕЗ выхода из комнаты
    стоимость 88, клеток 45
```

В E35S38 нет ни одной дороги и есть болота, а в домашней комнате E35S37 — 188
дорог вдоль южной границы. Поэтому **PathFinder честно выбирает обход через
домашнюю комнату**: 80 против 88 по стоимости. Это не ошибка поиска — это самый
дешёвый маршрут.

Сам по себе выход в домашнюю комнату безвреден (маршрут возвращается в E35S38
с востока, к источнику). Проблема — в реакции роли на смену комнаты.

## 3. Механизм пинг-понга

Было (`remote.miner`/`remote.hauler`):

```js
if (creep.room.name !== targetRoom) {
  ...
  creep.travelTo(new RoomPosition(25, 25, targetRoom));   // «иди в центр»
  return;
}
...
if (onBorder) {                                          // «уйди с кромки»
  creep.travelTo(new RoomPosition(25, 25, creep.room.name));
  return;
}
```

Цикл:

1. Крип в удалённой комнате у кромки (`(23,0)`), роль велит идти в центр →
   крип идёт вглубь комнаты (`(23,1)`).
2. Теперь роль видит, что крип в целевой комнате и не на кромке → рабочая цель
   `travelTo(source)` → **путь к источнику идёт на север, обратно через
   границу** (раздел 2) → крип делает шаг к домашней комнате.
3. Роль видит, что крип вне целевой комнаты → `travelTo((25,25,targetRoom))` →
   крип снова идёт в удалённую комнату. Из-за шага «назад» он оказывается на
   клетке кромки → ветка `onBorder` ещё раз разворачивает его к центру.
4. goto 1.

Цель рейса меняется каждые 1–2 тика (`25,25` ↔ источник), каждый раз Traveler
пересчитывает путь, и крип не удаляется от кромки дальше одной клетки — ни
источника, ни контейнера. В логах это выглядит как «не может перейти границу»,
хотя физически крип границу переходит каждый тик в обе стороны.

`reserver` не попал в петлю только потому, что маршрут к контроллеру
`(19,39)` внутри комнаты дешевле обхода, и роль не выводит его из комнаты.
Дефект у него тот же (цель подменяется точкой `(25,25)`), поэтому правка
сделана и в нём.

## 4. Что изменено

Правило одно: **цель рейса стабильна**. Точка `(25,25)` — только запасной
вариант, когда рабочая цель ещё ни разу не видна (первый заход/рейс).

| Файл | Было | Стало |
| --- | --- | --- |
| `remote.miner.js` | вне комнаты — всегда `(25,25,targetRoom)`; отдельная ветка `onBorder` → `(25,25,room)` | вне комнаты — контейнер/источник из памяти (`knownWorkTarget`), `(25,25)` только если цель неизвестна; ветка `onBorder` удалена |
| `remote.hauler.js` | вне `currentGoal` — `(25,25,currentGoal)`; отдельная ветка `onBorder` | вне `currentGoal` — линк/`storage` при доставке (`knownDeliverTarget`) или контейнер/ресурс/источник при сборе (`knownHaulTarget`); `onBorder` удалён |
| `remote.reserver.js` | вне комнаты — `(25,25,targetRoom)` | вне комнаты — запомненная позиция контроллера (`creep.memory.controllerPos`, пишется только при изменении) |

Кэш пути Traveler'а не тронут: `delete creep.memory._travel` при смене
комнаты оставлен как был, `serializePath`, `stuck`-логика, `maxOps` и
остальные оптимизации CPU не менялись.

## 6. Правка 18.09.2026: рабочая клетка контейнера задаётся конфигом

Живой снимок E35S38 сразу после правки из раздела 3 («пинг-понг») показал
дефект поменьше, но того же корня: майнер дошёл до источника, а **площадку
контейнера поставил под собой — (37,33)**:

```text
E35S38 roomObjects: source 36,32 | controller 19,39 | mineral 24,20
                    constructionSite container 37,33 (540/5000)
                    creep remoteMiner_E35S37_83055217 37,33 (store 20)
```

Вокруг источника (36,32) клетки (36,31), (36,33), (35,32) — стены террейна,
проходимый спутник с востока один — **(37,32)** (проверка:
`tests/analyze.terrain.js`; он же показывает, что маршрут из дома в комнату
заканчивается на (37,32)). Роль же ставила площадку через
`creep.pos.createConstructionSite`, то есть там, где крип остановился.

Что сделано:

- `constants.REMOTE.ROOM_TO_CONTAINER_POS` — одна точка правды «targetRoom →
  клетка контейнера» (рядом с `ROOM_TO_LINK`): `E35S38: (37,32)`,
  `E36S37: (21,11)` (там контейнер уже построен и стоит именно на этой клетке);
- `remote.miner`: пока контейнера нет, майнер идёт на настроенную клетку и
  ставит площадку ИМЕННО там (`configuredWorkCell`); если клетка для комнаты не
  настроена — прежнее поведение (любая клетка в радиусе 1 от источника, площадка
  под крипом). Уже стоящую площадку роль не переносит — иначе потерялся бы
  прогресс стройки;
- `tests/live.move.container.js` — живой инструмент правки: снимает площадки
  контейнера в комнате, ставит площадку в заданной клетке, сбрасывает у дальних
  майнеров комнаты кэш площадки (`containerSiteId`/`containerCheckedAt`) и
  проверяет результат отдельным запросом в новом тике;
- офлайн-харнесс `tests/remote.border.role.test.js` теперь мокает площадки и
  проверяет, что площадка появилась в (37,32), а майнер стоит на этой клетке.

Грабли API, найденные по ходу (важны для любых живых скриптов):

- консоль **молча игнорирует выражения длиннее ~1000 символов**: HTTP отвечает
  `ok`, а событие сокета приходит с пустым `results` (замер: 395 символов —
  ответ есть, 1044 — уже нет). Выражение собирается одной строкой, длина
  проверяется до отправки;
- `Room.find` кэшируется на тик: сразу после `createConstructionSite` список
  площадок в том же выражении ещё пуст (проверять только следующим тиком).

Живой итог: площадка контейнера в E35S38 стоит на **(37,32)** (0/5000). Прежний
майнер `remoteMiner_E35S37_83055217` к этому моменту умер сам (на клетке (37,33)
остался tombstone; число в имени — тик спавна), империя уже подняла нового
`remoteMiner_E35S37_83056772` — он достроит контейнер и встанет на него.

Деплой: в ветке `test` лежит `remote.miner` из раздела 3; чтобы роль брала
клетку из конфига, нужен `npx grunt screeps`.

## 7. Что осталось (не входило в правку)

- **Деплой.** Код в игре — ветка `test`; чтобы правка подействовала нужен
  `npx grunt screeps`. Локальные незакоммиченные правки `traveler.js`/
  `constants.js` при этом тоже уедут на шард — публиковать их можно только
  осознанно.
- **Контейнер в E35S38 ставится в настроенную клетку (37,32)** — см. раздел 6.
  На момент правки в комнате не было ни контейнера, ни площадки, поэтому площадку
  поставили заново инструментом `tests/live.move.container.js`; достраивает её
  новый майнер `remoteMiner_E35S37_83056772`, он же встанет на неё (клетка
  контейнера — рабочее место майнера). Если контейнер когда-нибудь снесут,
  площадка после деплоя конфига появится снова на (37,32).
- **Тот же рецепт для `defense.attacker.js`** (строки 79/117): он тоже ходит
  через `(25,25,targetRoom)`. Там это осмысленно — точка сбора и комната цели
  задаются вручную (`Memory.rallyOverride`), промежуточных рабочих целей у
  роли нет. Если появится настоящая цель в комнате — использовать тот же
  принцип «цель рейса стабильна».
- **Пинг-понг может вернуться при подмене цели по другим причинам.**
  Общее правило для любого роутера-роли: если путь к цели может выходить из
  комнаты, роль не должна переключать цель по факту смены комнаты, иначе
  получается тот же цикл. Проверять стоит любую новую роль с «точкой
  промежуточного сбора».
- `docs/TRAVELER-MIGRATION-DIFF.md` — исторический diff перевода на Traveler,
  он описывает прежнее поведение (`onBorder`, `(25,25,currentGoal)`); для
  `remote.miner`/`remote.hauler`/`remote.reserver` его актуальная версия —
  этот отчёт.
