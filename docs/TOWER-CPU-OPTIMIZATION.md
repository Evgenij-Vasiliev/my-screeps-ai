# TOWER-CPU-OPTIMIZATION

**Оптимизация башенной логики (`role.tower.js` / `runTowerLogic`)** — замеры на живом шарде и внесённые изменения.

---

## 1. Что измерялось и как

Замеры сняты на **живом шарде shard3** (не расчётные оценки):

| Источник | Что даёт |
| --- | --- |
| `Memory.cpuStats.profile` (23 316 тиков, накоплено профилировщиком ТЗ №0) | средний и максимальный CPU каждого бакета (`towers`, `roomState`, роли, подсистемы) |
| `memory.get` через `screeps-api` (токен из `Gruntfile.js`) | чтение профиля и Memory без нагрузки на игру |
| console-выражение с шарда, пишущее замеры в `Memory`, + чтение через API | адресные замеры (`Game.cpu.getUsed()` вокруг отдельных шагов) — в игре консольный результат приходит по websocket, поэтому результат пишется в Memory и вычитывается по HTTP |

Реплика для повторного замера (из корня репозитория):

```bash
node -e 'const{ScreepsAPI}=require("screeps-api");const a=new ScreepsAPI({token:"<TOKEN>"});a.memory.get("cpuStats.profile","shard3").then(r=>console.log(JSON.stringify(r.data,null,1)))'
```

## 3. Внесённые изменения

| Файл | Что сделано |
| --- | --- |
| `constants.js` | `TOWER.WALL_SCAN_INTERVAL: 15` (= `REPAIR_INTERVAL`), `TOWER.HITS_DROP_THRESHOLD: 1500` (порог «враг бьёт стены» на 1 тик) |
| `room.manager.js` | `detectAttack` заменён на `getWallHitsCache` (heap) + `scanWallsAndRamparts` (один проход, без `concat`/`map`/`filter`); добавлен `findHealers` (список лекарей считается один раз на комнату); тяжёлая часть `runTowerLogic` выполняется раз в `WALL_SCAN_INTERVAL` тиков; `underAttack` пишется только при изменении; `buildRoomState` больше не разыменовывает `walls`/`ramparts` |
| `role.tower.js` | только интенты; цели (`healers`, `wallTarget`, `damagedTarget`) приходят готовыми; добавлены проверки `inRangeTo(…, TOWER_FALLOFF_RANGE)` перед `attack`/`heal`/`repair`; удалён мёртвый `global._towerState` |
| `empire.js` | инициализация `global._towerWallHits` вместо `_towerState` |
| `types.d.ts` | убран `RoomMemory.lastWallHits`, добавлен `RoomMemory.wallThreshold` |

**Что не менялось:** скан врагов — по-прежнему каждый тик; лечение/атака — каждый тик; ремонт — раз в `REPAIR_INTERVAL`; пороги `REPAIR_ENERGY_MIN`, `WALL_THRESHOLD_*`, `SUPPLY_THRESHOLD` — без изменений.

### 3.1 Осознанное изменение поведения

- `attack`/`heal`/`repair` вызываются только если цель в радиусе `TOWER_FALLOFF_RANGE` (20). Раньше интент по недосягаемой цели выполнялся впустую и, из-за `return`, в этом тике глушил лечение и ремонт.
- «Просадка хитов стен» проверяется раз в 15 тиков вместо каждого. Порог масштабирован (`HITS_DROP_THRESHOLD × WALL_SCAN_INTERVAL`), чувствительность — те же 1500 хитов/тик. Сигнал остаётся вспомогательным: враг, бьющий стены, физически находится в комнате и уже найден `FIND_HOSTILE_CREEPS` каждый тик.

## 6. Как снять итоговые цифры после изменений

Окно профиля переносится в Memory только на тиках, где `Game.time % CPU.PROFILE_REPORT_INTERVAL === 0` (100 тиков), поэтому сразу после сброса видно «хвост» старого окна:

```
delete Memory.cpuStats.profile          // сбросить окно (в консоли игры)
```

Через ~20 тиков игрового времени в консоли игры появится строка `=== CPU PROFILE (ТЗ №0) …`, либо снаружи:

```bash
node /tmp/prof-report.js <TOKEN>   # avg/max/count по всем бакетам
```

Окно ждать не обязательно — его можно сбросить вручную и забрать накопленное (так сняты «тёплые» окна в 5.2):

```js
const c=require("cpuMonitor");const w=c.profileWindow;Memory.__wins=(Memory.__wins||[]).concat([{tick:Game.time,samples:w.samples,blocks:w.blocks}]);c.flushProfile();"ok"
```

Заметка по консоли игры: выражение-обёртка `(()=>{ … })()` возвращает в консоль `undefined` (побочные эффекты при этом выполняются) — для видимого результата пишите последовательность выражений через `;`, как в строке выше.

Профиль после Global Reset начинает новое окно с тика сброса (`startTick`), поэтому первые замеры «холодные»: `roomState` в них выше обычного (кэш структур пересобирается).
