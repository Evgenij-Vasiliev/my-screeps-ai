# Screeps — Архитектура зрелой империи

## Часть 4. Operation System (Система операций)

---

# Главная идея

После появления Task System возникает следующий вопрос:

```text
Кто создаёт задачи?
```

На раннем этапе ответ простой:

```text
Комната
```

Но по мере роста империи возникает проблема.

Некоторые процессы:

- работают сразу в нескольких комнатах;
- существуют тысячи тиков;
- используют десятки крипов;
- требуют собственных целей и логики.

Для таких процессов появляется новый уровень:

```text
Operation
```

---

# Что такое Operation

Operation — это долгоживущая цель высокого уровня.

Она описывает:

```text
Что нужно достичь
```

а не

```text
Что должен делать отдельный крип
```

---

# Сравнение уровней

```text
Empire
    ↓
Operation
    ↓
Tasks
    ↓
Creeps
```

---

# Пример

Империя принимает решение:

```text
Добывать энергию в W8N3
```

Это ещё не задачи.

Это операция.

Создаётся:

```js
{
    type: "remoteMining",
    targetRoom: "W8N3"
}
```

---

# Жизненный цикл операции

```text
Empire
    ↓
Create Operation
    ↓
Operation Active
    ↓
Generate Tasks
    ↓
Tasks Completed
    ↓
Goal Reached
    ↓
Operation Closed
```

---

# Главный принцип

Операция не выполняет работу.

Операция создаёт условия для выполнения работы.

---

# Почему нужны операции

Без операций получается:

```text
Комната A
Комната B
Комната C
```

каждая принимает решения самостоятельно.

---

С операциями:

```text
Empire
    ↓
Operation
    ↓
Несколько комнат
```

все работают на общую цель.

---

# Типичные виды операций

---

## Remote Mining Operation

Самая распространённая операция.

Цель:

```text
Получать ресурсы из удалённой комнаты
```

---

Состав:

```text
Miner
Hauler
Reserver
Defender
```

---

Операция сама создаёт задачи:

```text
Добыча
Перевозка
Резервирование
Оборона
```

---

## Claim Operation

Цель:

```text
Захватить новую комнату
```

---

Этапы:

```text
Разведка
↓
Отправка Claimer
↓
Захват
↓
Развитие
↓
Завершение
```

---

## Bootstrap Operation

Цель:

```text
Поднять новую комнату с нуля
```

---

Операция создаёт:

```text
Builder
Hauler
Upgrader
Support Convoys
```

---

Пока комната не станет самостоятельной.

---

## Military Operation

Цель:

```text
Атака
Оборона
Рейд
Осада
```

---

Пример:

```js
{
    type: "attack",
    targetRoom: "W7N2"
}
```

---

Операция определяет:

```text
Состав армии
Маршрут
Цели
Тактику
```

---

## Expansion Operation

Цель:

```text
Расширение империи
```

---

Операция может включать:

```text
Разведку
Оценку комнаты
Claim
Bootstrap
```

---

# Структура операции

Пример:

```js
{
    id: "op123",

    type: "remoteMining",

    status: "active",

    targetRoom: "W8N3",

    ownerRoom: "W8N2",

    priority: 80
}
```

---

# Состояние операции

Операция живёт через состояния.

Например:

```text
PLANNING
STARTING
ACTIVE
PAUSED
COMPLETED
FAILED
```

---

# Пример состояния

```js
{
  status: "active";
}
```

---

или

```js
{
  status: "completed";
}
```

---

# Операция как мини-государство

Полезная аналогия.

Комната похожа на город.

Империя похожа на страну.

Операция похожа на военную кампанию.

---

Она имеет:

```text
Цель
Ресурсы
Персонал
Бюджет
Приоритет
```

---

# Бюджет операции

Очень сильная концепция.

Например:

```js
{
    maxHaulers: 3,
    maxMiners: 2,
    energyBudget: 5000
}
```

---

Операция не может бесконечно потреблять ресурсы империи.

---

# Ownership

Каждая задача должна иметь владельца.

Пример:

```js
{
    taskId: "task1",
    operationId: "op123"
}
```

---

Тогда всегда понятно:

```text
Кто создал задачу
Зачем она существует
Когда её удалить
```

---

# Генерация задач

Операция создаёт задачи автоматически.

Пример:

```text
Remote Mining Operation
```

видит:

```text
Контейнер заполнен
```

создаёт:

```js
{
  type: "haul";
}
```

---

Видит:

```text
Резерв заканчивается
```

создаёт:

```js
{
  type: "reserve";
}
```

---

# Operation Controller

Каждая операция обычно имеет собственный контроллер.

```text
Operation
       ↓
Operation Controller
       ↓
Tasks
```

---

Контроллер анализирует ситуацию.

Создаёт новые задачи.

Удаляет старые задачи.

Завершает операцию.

---

# Operation Manager

На уровне империи существует менеджер операций.

```text
Empire
     ↓
Operation Manager
     ↓
Operations
```

---

Пример структуры:

```text
operations/

├─ operation.manager.js
├─ operation.base.js
├─ operation.remoteMining.js
├─ operation.claim.js
├─ operation.bootstrap.js
├─ operation.attack.js
└─ operation.expansion.js
```

---

# Базовый интерфейс

Все операции обычно реализуют одинаковые методы.

```js
operation.init();

operation.run();

operation.generateTasks();

operation.complete();

operation.cancel();
```

---

# Operation против Room

Плохая архитектура:

```text
Room управляет Remote Mining
```

---

Проблема:

```text
Логика размазывается по комнате
```

---

Хорошая архитектура:

```text
Operation управляет Remote Mining
```

---

Комната становится исполнителем.

---

# Масштабирование

При увеличении размеров империи:

```text
5 комнат
20 комнат
50 комнат
100 комнат
```

число операций растёт естественно.

---

Например:

```text
7 Remote Mining
3 Bootstrap
2 Attack
1 Expansion
```

---

Империя начинает управлять операциями, а не комнатами.

---

# Полная цепочка управления

```text
Empire
    ↓
Operations
    ↓
Policies
    ↓
Tasks
    ↓
Scheduler
    ↓
Dispatcher
    ↓
Executors
    ↓
Creeps
```

---

# Главный архитектурный эффект

Operation System позволяет отделить:

```text
Стратегию
от
Тактики
```

---

Империя говорит:

```text
Освоить комнату W8N3
```

---

Операция решает:

```text
Какие ресурсы нужны
Какие крипы нужны
Какие задачи создать
```

---

Крипы просто работают.

---

# Главные выводы

1. Operation — долгоживущая цель высокого уровня.

2. Операции находятся между Империей и Task System.

3. Операции могут охватывать несколько комнат.

4. Операции создают задачи.

5. Операции обладают собственным состоянием.

6. Операции обладают собственным бюджетом.

7. Операции значительно упрощают масштабирование империи.

8. Империя управляет операциями, а не отдельными крипами.
