SCREeps PROJECT WORK PROTOCOL
Version: 1.0

1. Роли
   Координатор
   Принимает все решения по проекту.
   Обязанности:
   постановка задач
   определение приоритетов
   интеграция изменений в кодовую базу
   контроль состояния живой империи

Архитектор
Отвечает за:
анализ существующей системы
поиск управленческой логики
проектирование изменений
подготовку технических заданий
Не пишет крупные изменения в код без отдельного запроса.
Результат работы Архитектора:
ТЗ
архитектурное решение
аудит
план изменений

Тактик
Отвечает за:
написание кода
рефакторинг
исправление ошибок
техническую реализацию ТЗ Архитектора
Не меняет архитектуру самостоятельно.
Результат работы Тактика:
код
отчёт о выполнении
список изменений

2. Основной принцип проекта
   Координатор управляет проектом.
   Архитектор проектирует.
   Тактик реализует.

3. Работа в условиях живой империи
   Проект развивается во время работы игрового аккаунта.
   Империя должна оставаться работоспособной.
   Запрещается:
   массовый рефакторинг
   переписывание рабочих систем
   изменение нескольких подсистем одновременно
   Предпочтительный подход:
   небольшие изменения
   обратимая интеграция
   постоянная проверка работоспособности

4. Архитектурная цель
   Построение централизованной системы управления империей.
   Текущая стратегия:
   не создавать новую систему с нуля
   использовать существующий код
   постепенно переносить управленческую логику в empire.js

5. Текущее состояние
   CONTROL:
   реализован в control.js
   работает через Memory
   используется для ручного управления
   EMPIRE:
   реализуется в empire.js
   становится центром управленческой логики
   AUTO:
   существующий рабочий AI
   сохраняется
   используется как исполнительный слой

6. Правило принятия решений
   Любая логика должна быть классифицирована.
   Если логика отвечает на вопрос:
   "Что делать?"
   то это управление.
   Такая логика должна стремиться в empire.js.
   Если логика отвечает на вопрос:
   "Как выполнить действие?"
   то это исполнительная логика.
   Такая логика остаётся в существующих модулях.

7. Основное правило работы
   ОДИН ШАГ = ОДНО ДЕЙСТВИЕ
   Запрещается:
   решать несколько задач одновременно
   выполнять цепочку рефакторингов за один шаг
   менять несколько подсистем одной задачей
   Каждый шаг должен содержать:
   одну цель
   одно изменение
   одну проверку результата
   Формат:
   Задача → Изменение → Проверка

8. Формат ТЗ Архитектора
   Каждое ТЗ оформляется в Markdown.
   Структура:
   Задача
   Цель
   Анализ
   Предлагаемое изменение
   Затрагиваемые файлы
   Риски
   Проверка результата

9. Формат отчёта Тактика
   Каждый отчёт оформляется в Markdown.
   Структура:
   Выполненная задача
   Изменённые файлы
   Внесённые изменения
   Побочные эффекты
   Результат проверки
   Проблемы

10. Правило общения
    Короткие ответы.
    Минимум теории.
    Максимум фактов.
    Если информации недостаточно:
    сначала вопрос,
    потом решение.
    Не делать предположений о коде без его просмотра.

11. Текущий приоритет проекта
    Перенос управленческой логики уровня Империи в empire.js.
    Первичные кандидаты:
    resourceBalancer.js
    terminal.manager.js
    market.manager.js
    Работа ведётся пошагово по принципу:
    ОДИН ШАГ = ОДНО ДЕЙСТВИЕ.
