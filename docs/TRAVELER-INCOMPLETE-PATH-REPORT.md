- Дата: 2026-09-18

---

## 1. Что означает строка

`TRAVELER: incomplete path` печатается ровно в одном месте — `traveler.js:276` (до правки):

```js
let ret = this.findTravelPath(creep, destPos, options);
...
if (ret.incomplete) { console.log(`TRAVELER: incomplete path for ${creep.name}`); ... }
```

`ret.incomplete === true` — это ответ `PathFinder.search`: **за `maxOps` (20000) не найдено ни одной клетки в радиусе `range` (по умолчанию 1) от цели**. То есть это не ошибка кода и не «крип сломался», а признание поиска, что маршрут до цели в текущей матрице не сходится. Крип при этом получает частичный путь (к ближайшей достижимой клетке) и продолжает движение.

---

## 2. Причина: это пробка, а не отсутствие маршрута

Traveler ищет путь **двумя разными матрицами**:

| Ситуация | Матрица | Крипы как препятствия |
| --- | --- | --- |
| Обычный поиск (`travelTo` каждый тик) | `getStructureMatrix` (только стены/структуры) | нет |
| После застревания: `travelData.stuck >= defaultStuckValue` (3 тика на одной клетке) | `getCreepMatrix` (структуры + **все** крипы) | да |

`incomplete` в наблюдаемом логе приходит из **второй** ветки — когда крип 3 тика не мог сдвинуться (его зажимают другие крипы) и Traveler пересчитал маршрут «с крипами».

### 2.1 Замер 1: структурно все цели комнаты достижимы

BFS по комнате `E35S39` (террейн + структуры из `roomObjects`, крипы игнорируются; не блокируют: дороги, контейнеры, свои рампы, источники, минерал, надгробия, контроллер):

```text
open tiles (no creeps): 988
targets whose range-1 neighbourhood is NOT reachable: 0
```

**Ни одной** структуры с зажатой целью (у каждой есть хотя бы одна достижимая подходная клетка). Значит «нет маршрута» тут ни при чём.

### 2.2 Замер 2: при структурной матрице лог не воспроизводится

49 опросов игровой консоли подряд (каждые ~4 с, ~4 минуты) — для каждого крипа империи `findTravelPath(creep, memory._travel.dest)` тем же кодом Traveler:

```text
default (structure) matrix incomplete: 0
creep matrix incomplete:               0
```

Ноль срабатываний в спокойной фазе — лог появляется только в момент пробки.

### 2.3 Почему пробка возможна именно в узле базы E35S39

Подходные клетки у целей узла (карта `E35S39`, окно x=20..42; `T` — storage, `M` — терминал, `L` — лаба, `@` — крип):

```text
13   ... r  # # # # # # #  k  @ @  r  L .
14   ... # # # # # # # #  @  T  r  r  r .
15   ... # # # # # # #  @  M  L  L  L  r  L  L  L  r
16   ... # # # # # #  r  r  r  @  @  r  r  r
```

- `storage` (29,14): всего 3 проходимые подхода — `(28,14)`, `(29,13)`, `(30,14)` (остальное — терминал, лаборатории, линк).
- `terminal` (28,15): 5 подходов — `(27,15)`, `(28,14)`, `(27,16)`, `(28,16)`, `(29,16)`.
- Лаборатории троек — то же: подход 2–5 клеток, всё остальное занято соседними лабами/реактором.

Одновременно в этом узле работают 6 из ~10 крипов комнаты (в момент разбора: `harvester` на (27,15), `worker` на (28,14), `labWorker` на (29,16), `worker` на (30,16), `linkWorker` на (29,13), `miner` на (30,13)). Если в момент пересчёта «с крипами» кольцо подходов занято — PathFinder честно возвращает `incomplete`.

Именно поэтому в логе только `worker` и `labWorker`: это две роли, которые в узле базы ходят `travelTo` чаще всех (у `harvester` свой дешёвый прямой шаг, у `miner`/`linkWorker` рейсов мало).

### 2.4 Почему строки повторяются каждые ~10 секунд

`stuck` сбрасывается в 0 сразу после любого пересчёта (`traveler.js:293`). Цикл в пробке: 3 тика без движения → пересчёт «с крипами» → `incomplete` (лог) → следующий тик снова обычный поиск по структурам, путь сходится, крип едет → снова упирается в соседа… Отсюда «одна строка на каждые несколько тиков» у каждого зажатого крипа.

## 3. Что изменено

1. **Дедупликация и информативность лога.** Новый метод `Traveler.handleIncomplete()` пишет сообщение один раз на пару «крип + цель» и не чаще `incompleteReportCooldown` (50 тиков) для одной и той же цели; новая цель сбрасывает «уже жаловались». В строке теперь есть цель, позиция, `ops`, длина пути, режим матрицы и `stuck`:

   ```text
   TRAVELER: incomplete path for worker_E35S39_83054083, dest: [room E35S39 pos 29,14], pos: [room E35S39 pos 30,16], ops: 12, path: 0, creepsAsWalls: yes, stuck: 3
   ```

   Вторая строка (`attempting path without findRoute was …`) убрана — её информация теперь в общей строке.

2. **Откат на структурную матрицу.** Если поиск «с крипами» вернул `incomplete`, Traveler повторяет поиск по структурной матрице (`ignoreCreeps: true`) и берёт его результат, если он полнее. Крип получает валидный маршрут вместо пустого/частичного, и лог в пробке перестаёт быть симптомом «крип без пути». Прежний retry (`useFindRoute = false`, только для обычной матрицы) сохранён как есть.

3. **Пауза при полном отсутствии пути.** Если после всех попыток путей нет вообще (`path.length === 0`), следующий поиск откладывается на `noPathRetryTicks` (5 тиков) — раньше `PathFinder.search` вызывался в таком случае каждый тик впустую. Смена цели сбрасывает паузу.

4. Новые опции задокументированы в шапке `traveler.js`: `incompleteReportCooldown: 50`, `noPathRetryTicks: 5`.

### 3.1 Что не менялось

- Архитектура и порядок поиска (структурная матрица → «с крипами» при застревании), кэши матриц, `serializePath`, `stuck`-логика, `maxOps`/`range`/`reusePath` — без изменений.
- Роли и Task System не тронуты. Пробка в узле базы остаётся физической (место мало, крипов много) — правка убирает спам и лишние поиски, но не «расширяет» узел.

## 5. Что осталось (не входило в правку)

- **Пробка физическая.** `storage`/`terminal`/лабы в E35S39 стоят плотным блоком, и 6–10 крипов крутятся вокруг 3–5 подходных клеток. Если хочется убрать пробку, а не только её диагностику, надо разводить расписания ролей (например, не пускать `harvester` и `worker` в один и тот же узел одним тиком) — это отдельная задача.
- `Memory.empire.hostileRooms` в живом Memory пуст (`{"rooms":5,"hostileRooms":{}}`), поэтому фильтр враждебных комнат на этот лог не влиял — но остаётся дефектом №14 аудита (в `Memory.empire` никто, кроме Traveler, ничего не пишет).
- Код в игре — ветка `test`; чтобы правка попала на шард, нужен деплой (`npx grunt screeps`), локальные правки `constants.js` при этом тоже уедут.
