# План лабораторного производства бустов — «Новая Империя»

## 1. Цель

Подготовить лабораторную систему к постоянной добыче в SK-комнате **E35S36**.

E35S36 рассматривается не как разовая экспедиция, а как постоянный remote-контур:

- постоянная добыча энергии;
- постоянная добыча минерала O;
- постоянная работа с Source Keeper;
- постоянная потребность в боевых и экономических бустах.

**E35S37 — центральный хаб и единственная комната финального производства бустов.**

Остальные четыре комнаты производят только промежуточные компоненты и передают их в E35S37.

В каждой обычной комнате отдельная boost-lab используется для бустирования местных крипов.

---

## 2. Основной принцип производства

Производственные лабораторные тройки не работают с одним рецептом навсегда.

Каждая тройка получает **два рецепта** и переключается между ними по запасам:

```text
Тройка
  │
  ├── Рецепт A → накопить целевой запас
  │
  └── Рецепт B → накопить целевой запас
```

Переключение выполняется по дефициту, а не по фиксированному таймеру.

Правило:

```text
если A ниже минимального запаса → варим A
иначе если B ниже минимального запаса → варим B
иначе → тройка свободна / занимается резервным рецептом
```

Не допускается постоянное переключение A/B около границы. Нужен гистерезис: переходить на другой рецепт только после достижения верхней границы текущего запаса.

**Цель:** не варить всё одновременно, а поддерживать устойчивый запас компонентов для непрерывного конечного производства.

# 4. Постоянный набор конечных бустов

## Экономика SK

```text
Remote Miner  → XUHO2 + XZHO2
Remote Hauler → XKH2O + XZHO2
```

## Боевая группа SK

```text
Attack/Ranged → XKHO2 + XZHO2
Tough         → XGHO2 + XZHO2
Healer        → XLHO2 + XZHO2
```

MOVE (`XZHO2`) является общим конечным бустом для обоих контуров.

## Обычные комнаты

Первый локальный буст для обычных Worker — **XKH2O (CARRY)**.

Причина: Worker у нас постоянно выполняет задачи внутренней логистики, поэтому усиление CARRY используется во множестве задач Task System.

Второй кандидат после накопления достаточного запаса XKH2O — **XZHO2 (MOVE)**.

WORK-бусты обычным комнатам массово не приоритетны: `XUHO2` резервируется прежде всего для постоянных remote miners SK.

Для финальных бустов нужны шесть промежуточных компонентов:

```text

KHO2 → XKHO2
UHO2 → XUHO2
ZHO2 → XZHO2
GHO2 → XGHO2
LHO2 → XLHO2
```

# 9. Буферизация

Производство должно быть ориентировано на склад E35S37, а не на немедленное применение каждым следующим криером.

Начальная политика запасов:

| Конечный продукт | Стартовый целевой запас |
|---|---:|
| XKH2O | 3000 |
| XZHO2 | 5000 |
| XUHO2 | 3000 |
| XKHO2 | 3000 |
| XGHO2 | 3000 |
| XLHO2 | 3000 |

Это **стартовые значения**, а не окончательные экономические нормы. После появления реальной статистики потребления они должны корректироваться по расходу.

Для промежуточных компонентов целевой запас должен быть ниже конечного и достаточным для непрерывной работы финальной тройки; первоначально использовать тот же принцип дефицит/цель, без жёсткого равенства всех буферов.

# 10. Правило переключения двух рецептов

Для каждой производственной тройки:

```text
1. Проверить дефицит A.
2. Если A ниже LOW_A → варить A.
3. Иначе проверить дефицит B.
4. Если B ниже LOW_B → варить B.
5. Иначе остановить тройку или использовать резервный рецепт.
```

После достижения `HIGH_A` можно переключить тройку на B.

Нельзя переключаться каждый тик между A и B.

Нужны отдельные LOW/HIGH пороги:

```text
LOW < HIGH
```

Это исключает дребезг производства.

# 11. Управление E35S37

E35S37 должна быть конечной точкой всей химической цепочки.

Для каждой из трёх финальных троек:

```text
если промежуточный компонент есть
и X есть
и конечного буста меньше LOW
→ варить конечный буст
```

При достижении HIGH:

```text
→ переключиться на второй конечный буст тройки
```

Таким образом:

```text
T1: XKH2O ↔ XKHO2
T2: XUHO2 ↔ XZHO2
T3: XGHO2 ↔ XLHO2
```

# 12. Boost-lab обычных комнат

В каждой обычной комнате отдельная boost-lab используется для уже произведённых бустов.

Первая фаза:

```text
Boost-lab → XKH2O → Worker CARRY
```

Не использовать production-triple для непосредственного бустирования. Production остаётся отделённым от boost-lab.

После стабилизации XKH2O можно добавить:

```text
Boost-lab → XZHO2 → MOVE
```

но приоритет — CARRY.

```text
XUHO2 + XZHO2
```

Главная цель — максимально долго держать boosted miner на источнике 4000 energy и минерале O.

```text
XKH2O + XZHO2
```

Цель — быстро забирать накопленную энергию и минерал, не допуская переполнения контейнера.

## Резерв

Боевые и добывающие бусты хранятся в E35S37 и выдаются по роли перед отправкой/заменой крипов.

# 17. Важные запреты

- Не варить конечные X-бусты вне E35S37.
- Не использовать boost-lab как production-lab.
- Не пытаться одновременно запускать два рецепта в одной тройке.
- Не переключать рецепты каждый тик.
- Не расходовать резерв `XUHO2` на обычных Worker.
- Не расходовать боевые `XKHO2/XGHO2/XLHO2` на мирных крипов.
- Не создавать новую глобальную систему задач для лабораторий: использовать существующие `lab.manager.js`, `lab.worker.js`, Task System и текущую конфигурацию Memory.
