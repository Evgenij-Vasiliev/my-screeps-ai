# Screeps — Архитектура зрелой империи

## Часть 5. Policy System (Система политик)

---

# Главная идея

После появления:

```text id="k1t4ja"
Empire
↓
Operations
↓
Tasks
↓
Creeps
```

возникает новый вопрос:

```text id="m5x8qr"
Как Империя влияет на поведение системы?
```

Наивный подход:

```text id="cfy8rv"
Империя напрямую отдаёт команды.
```

Но это приводит к постоянному микроменеджменту.

В зрелой архитектуре используется другой подход:

```text id="f7o7iw"
Империя публикует политики.
```

Системы сами подстраивают своё поведение под действующие политики.

---

# Что такое Policy

Политика (Policy) — это набор правил и ограничений.

Политика отвечает не на вопрос:

```text id="d5f7s4"
Что делать прямо сейчас?
```

а на вопрос:

```text id="f3lfu0"
Что разрешено делать?
Что запрещено делать?
Что предпочтительно делать?
```

---

# Аналогия

Империя похожа на государство.

Комнаты похожи на города.

Системы похожи на службы города.

---

Государство не говорит каждому человеку:

```text id="x7v6zu"
Поверни направо.
Поверни налево.
```

Оно публикует законы и правила.

---

Точно так же работает Policy System.

---

# Иерархия управления

```text id="yrm0ik"
Empire
    ↓
Policies
    ↓
Systems
    ↓
Tasks
    ↓
Creeps
```

---

# Главное преимущество

Без политик:

```text id="nlm0yx"
Империя должна управлять каждой системой отдельно.
```

С политиками:

```text id="0czx0w"
Империя меняет одно правило.
Вся система меняет поведение.
```

---

# Пример энергетической политики

Политика:

```js id="v7l3qx"
{
    upgrade: false,
    build: false,
    repair: true
}
```

---

Что происходит?

```text id="5lmbol"
Апгрейд отключён
Строительство отключено
Ремонт разрешён
```

---

Ни один крип не получил команду.

Но поведение всей комнаты изменилось.

---

# Типы политик

---

## Energy Policy

Управляет расходованием энергии.

Пример:

```js id="s0mj0d"
{
    upgradeAllowed: true,
    buildAllowed: true,
    reserveEnergy: 50000
}
```

---

Назначение:

```text id="v5j5bn"
Контроль энергетического бюджета.
```

---

## Spawn Policy

Управляет производством крипов.

Пример:

```js id="wq0xhb"
{
    spawnMilitary: false,
    spawnBuilders: true,
    spawnHaulers: true
}
```

---

Назначение:

```text id="l0w7k6"
Контроль численности населения.
```

---

## Military Policy

Управляет военной активностью.

Пример:

```js id="dzij2n"
{
    attackAllowed: false,
    defendAllowed: true
}
```

---

---

## Expansion Policy

Управляет ростом империи.

Пример:

```js id="0rjv8k"
{
    allowExpansion: true,
    maxColonies: 8
}
```

---

---

## Market Policy

Управляет торговлей.

Пример:

```js id="5e6z0m"
{
    buyEnergy: false,
    sellExcessEnergy: true
}
```

---

# Уровни политик

Политики могут существовать на разных уровнях.

---

## Имперский уровень

```js id="x9sl9v"
Empire Policy
```

Пример:

```js id="c2s57f"
{
  economyMode: "save";
}
```

---

Действует на всю империю.

---

## Уровень операции

Пример:

```js id="8m4r1h"
{
  aggressive: true;
}
```

---

Применяется только к конкретной операции.

---

## Уровень комнаты

Пример:

```js id="svq9mx"
{
  upgradeAllowed: false;
}
```

---

Влияет только на одну комнату.

---

# Наследование политик

Очень мощная концепция.

---

Империя публикует:

```js id="q4v7ki"
{
  economyMode: "save";
}
```

---

Комната наследует её.

---

Получаем:

```text id="r4yq3i"
Empire Policy
        ↓
Room Policy
        ↓
System Policy
```

---

Каждый уровень может уточнять предыдущий.

---

# Пример наследования

Империя:

```js id="k8v4c7"
{
  upgradeAllowed: true;
}
```

---

Комната:

```js id="d5w3m8"
{
  upgradeAllowed: false;
}
```

---

Итог:

```text id="x7u5n0"
Для данной комнаты апгрейд запрещён.
```

---

# Политики вместо условий

Плохой подход:

```js id="e2w8g6"
if(storage.store.energy < 10000)
{
    ...
}
```

---

Такие проверки начинают дублироваться во всём проекте.

---

Хороший подход:

```js id="q1n6r4"
if (!policy.upgradeAllowed) {
  return;
}
```

---

Система больше не знает причин.

Она знает только правила.

---

# Политики и состояния

Очень часто политики строятся на основе состояний.

---

Сначала вычисляется состояние:

```text id="v2f7q5"
CRITICAL
LOW
NORMAL
SURPLUS
```

---

Потом формируется политика.

---

Например:

```text id="u8p6j9"
CRITICAL
```

превращается в:

```js id="m4d8k1"
{
    upgradeAllowed: false,
    buildAllowed: false,
    repairAllowed: true
}
```

---

# Главный архитектурный эффект

Policy System позволяет отделить:

```text id="x6n3r1"
Принятие решений
от
Исполнения решений
```

---

Империя принимает решение.

Политика публикует ограничения.

Системы подстраиваются автоматически.

# Главные выводы

1. Policy — это набор правил, а не команд.

2. Политики связывают стратегию и исполнение.

3. Политики могут существовать на уровнях Империи, Операции и Комнаты.

4. Политики часто формируются на основе состояний.

5. Системы должны опираться на политики, а не на собственные проверки.

6. Политики позволяют менять поведение всей империи одной настройкой.

7. Чем меньше прямого управления, тем проще масштабировать архитектуру.

# Следующая тема

State System

Самый фундаментальный уровень зрелой архитектуры.

Потому что политики не появляются сами по себе.

Сначала система должна понять:

```text id="z4r7p2"
Что происходит в мире?
```

Именно этим занимается State System.
