# Screeps — Архитектура зрелой империи

## Часть 13. Goal System (Система целей)

---

# Главная идея

Многие архитектуры заканчиваются на Strategy System.

---

Они работают примерно так:

```text
ECONOMY

DEFENSE

EXPAND

WAR
```

---

Но возникает проблема.

---

Откуда стратегия знает:

```text
Что именно нужно делать?
```

---

Ответ:

```text
Из целей.
```

---

Goal System является источником всех долгосрочных намерений империи.

---

# Главное различие

Очень важно понимать.

---

Goal System отвечает:

```text
Чего хочет достичь империя?
```

---

Strategy отвечает:

```text
Какая цель сейчас важнее?
```

---

Это разные уровни.

---

# Аналогия

Представим государство.

---

Цели:

```text
Повысить ВВП

Увеличить население

Укрепить оборону

Развить промышленность
```

---

Стратегия:

```text
В этом году важнее оборона.
```

---

# Goal как объект

В зрелой архитектуре цель является отдельной сущностью.

---

Пример:

```js
{
    id: "expand_10_rooms",

    type: "expansion"
}
```

---

Цель существует независимо от текущей стратегии.

---

# Свойства цели

Обычно цель содержит:

```js
{
  id, type, priority, progress, target, status;
}
```

---

# Пример

```js
{
    id: "energy_stockpile",

    target: 1000000,

    progress: 650000
}
```

---

Империя знает:

```text
Цель выполнена на 65%
```

---

# Измеримость

Очень важный принцип.

---

Плохая цель:

```text
Стать сильнее.
```

---

Хорошая цель:

```text
Накопить 1 000 000 энергии.
```

---

Потому что её можно измерить.

# Иерархия целей

Очень мощная концепция.

---

Большие цели разбиваются на подцели.

---

Пример:

```text
Иметь 10 комнат
```

---

Разбивается на:

```text
Найти комнату

↓

Захватить комнату

↓

Развить комнату

↓

Интегрировать в империю
```

---

# Goal Tree

Получается дерево.

---

```text
10 Rooms
│
├─ Room 7
├─ Room 8
├─ Room 9
└─ Room 10
```

---

Каждая подцель имеет собственный прогресс.

---

# Goal Progress

Прогресс должен вычисляться автоматически.

---

Например:

```js
progress = currentRooms / targetRooms;
```

---

Результат:

```text
70%
```

---

# Goal Score

Часто используется оценка полезности.

---

Например:

```js
{
    goal: "expand",

    score: 85
}
```

---

Чем выше score, тем привлекательнее цель.

---

# Goal Priority

Отдельный параметр.

---

Например:

```js
{
  priority: 100;
}
```

---

или:

```js
{
  priority: 20;
}
```

---

Приоритет определяет важность.

---

# Конфликт целей

Одна из самых сложных задач.

---

Например:

```text
Копить энергию
```

и

```text
Расширяться
```

---

используют одни ресурсы.

---

Обе цели невозможно выполнить максимально быстро одновременно.

---

Goal System должна уметь сообщать:

```text
Цели конфликтуют.
```

---

# Goal Evaluation

Система постоянно пересматривает цели.

---

Например:

```text
Цель потеряла актуальность.
```

---

или:

```text
Появилась более выгодная цель.
```

---


# Главный архитектурный эффект

После появления Goal System игрок перестаёт видеть:

```text
Набор задач
```

---

Он начинает видеть:

```text
Портфель целей
```

---

Как руководитель компании видит не сотрудников и отдельные поручения, а набор стратегических целей организации.

# Goal System и автономность

Это один из последних шагов к автономной империи.

---

Потому что появляется возможность:

```text
Самостоятельно создавать цели

Самостоятельно оценивать цели

Самостоятельно завершать цели

Самостоятельно выбирать цели
```

---

Без прямого участия игрока.

---

# Главные выводы

1. Goal System определяет, чего хочет достичь империя.

2. Цели существуют независимо от стратегии.

3. Цели должны быть измеримыми.

4. Каждая цель имеет прогресс и статус.

5. Большие цели разбиваются на подцели.

6. Цели могут конфликтовать между собой.

7. Стратегия выбирает цели, а не придумывает их.

8. Goal System является фундаментом автономного управления.
