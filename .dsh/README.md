# .dsh — кастомный агент для разработки бота Screeps

Каталог содержит две вещи:

| Путь | Что это | Кто читает |
|---|---|---|
| `.dsh/skills/<name>/SKILL.md` | база знаний: 9 скиллов по API Screeps и практикам игры | провайдер `skill-filesystem` DSH, корень `project-dsh` (ранг 100) |
| `.dsh/preset/screeps-dev/` | agent preset «Screeps: разработка бота»: персона + набор инструментов | ростер пресетов DSH после установки в `~/.dsh/.agent-presets/` |

Скиллы лежат в репозитории и версионируются вместе с кодом бота: их видит
любая сессия, чей рабочий каталог — этот репозиторий (project root = ближайший
предок с `.git`), независимо от выбранного пресета. Пресет добавляет к этому
персону (правила проекта, язык, порядок работы) и полный набор инструментов
кодинг-агента.

## Скиллы

| Скилл | О чём |
|---|---|
| `screeps-api-core` | Game/Room/Creep/Structure/Store, константы, коды ошибок, старое vs новое API |
| `screeps-cpu-memory` | лимиты CPU и bucket, heap vs Memory, сериализация, RawMemory, бюджеты |
| `screeps-economy` | RCL-прогрессия, арифметика энергии, квоты ролей, спавн, links/labs/factory |
| `screeps-movement-pathfinding` | движение, fatigue, PathFinder, CostMatrix, кэш путей, трафик |
| `screeps-defense-combat` | башни, бой, бусты, стены/рампы, safe mode, инвейдеры, nuke |
| `screeps-market-terminal` | ордера, комиссии, стоимость отправки, бюджет и риски |
| `screeps-architecture-testing` | архитектура этого бота, паттерны, тесты локально vs на шарде |
| `screeps-power-intershard` | power creeps, ops, порталы, InterShardMemory |
| `screeps-live-measurement` | правила проекта, baseline.js, лимиты консоли, протокол замера |

Каждый скилл начинается с YAML frontmatter (`name`, `description`, `whenToUse`)
и заканчивается секцией «Источники» со ссылками, по которым факт проверен.
Числа и формулы без источника помечены как непроверенные — это требование
`AGENTS.md` («каждое утверждение — либо файл:строка, либо цифра из замера»).

## Установка пресета

Пресет обязан лежать в пользовательском корне DSH, поэтому после правок в
`.dsh/preset/screeps-dev/` его нужно скопировать:

```bash
mkdir -p ~/.dsh/.agent-presets
rm -rf ~/.dsh/.agent-presets/screeps-dev
cp -R .dsh/preset/screeps-dev ~/.dsh/.agent-presets/screeps-dev
```

Дальше — создать новую сессию и выбрать режим «Screeps: разработка бота» в
выборе агента. Переключить уже начатую сессию нельзя: пресет меняет набор
инструментов, а сессия с историей вызовов на другой набор не переводится
(ограничение `dsh-agent-presets`, не этого пресета).

## Проверка

```bash
node scripts/validate.preset.js   # preset.yml + agent.cordis.yml + наличие скиллов
node scripts/validate.skills.js   # frontmatter, имена, синтаксис js-блоков
```

Оба скрипта ничего не меняют и не ходят в сеть. Ненулевой код возврата —
есть ошибки. `validate.preset.js` проверяет те же условия, по которым ростер
DSH отбраковывает пресет при монтировании: разбираемость YAML, наличие
`id`/`name`, установленность каждого пакета в деплое DSH и обязательные поля
config (`persona.prefix`, `plan-mode.section`, `tool-subagent.provider`).
Он же предупреждает, если установленная в `~/.dsh` копия разошлась с
репозиторием.

`validate.skills.js` ловит то, из-за чего провайдер молча выбрасывает скилл из
каталога сессии: невалидный YAML frontmatter (например незакавыченное
`description: текст: продолжение` — на этом уже спотыкались три скилла),
несовпадение `name` с именем каталога, устаревшие поля
`disableModelInvocation` / `userInvocable`, некомпилирующиеся `js`-блоки.
Разбор frontmatter идёт настоящим парсером `js-yaml` — он берётся из
`node_modules` проекта (транзитивная зависимость grunt) или из
`~/.dsh/profiles/node_modules`; если его нет нигде, скрипт сообщает об этом и
возвращает 1.

## Как это проверено

| Утверждение | Чем проверено |
|---|---|
| каталог `.dsh/skills` реально попадает в каталог скиллов живой сессии | создан пробный скилл `.dsh/skills/zz-probe/SKILL.md` — он появился в каталоге скиллов сессии без перезапуска хоста (и исчез после удаления) |
| пресет `screeps-dev` проходит Discovery деплоя | вызов кода самого DSH: `scanRoot({path:'~/.dsh/.agent-presets', trust:'user'})` из `@deepseek-ai/dsh-agent-presets/lib/types/discovery.js` вернул `{id: 'screeps-dev', name: 'Screeps: разработка бота', broken: null}` — то есть все строки композиции резолвятся в установленные пакеты |
| `preset.yml` и обязательные поля config | `node scripts/validate.preset.js` |

Пресет не несёт скиллов внутри себя: их читает провайдер из корня проекта,
поэтому сессия должна быть открыта на этом репозитории (рабочий каталог —
`newScreeps`). В другом репозитории пресет даст персону и инструменты, но не
базу знаний — персона это оговаривает явно.

## Откат

- Скиллы: `git checkout -- .dsh/skills` (или удалить каталог скилла).
- Пресет: `rm -rf ~/.dsh/.agent-presets/screeps-dev`. Уже запущенные сессии
  продолжают работать на своей версии композиции, новые — не увидят пресет.

Ни один файл бота (`main.js`, `*.manager.js`, `role.*.js`, `task.*.js`) этим
каталогом не затрагивается, и на шард он не уезжает: выгрузка берёт только
`["*.js", "constants/*.js", "room/*.js", "task/*.js"]` (`scripts/deploy.modules.js:49`), а `Gruntfile.js`
лишь вызывает эту сборку.
